# 岗位画像与简历初筛设计参考

配套专家包：tingyun-recruiting-system（招聘流程与面试评价顾问）

本文件给出可直接抄用的画像表、胜任力模型表与初筛模板。所有内容为一般性参考。

---

## 一、岗位画像表（四项齐全才算写完）

| 组成 | 填写要求 | 反例 | 正例 |
|---|---|---|---|
| 岗位使命 | 一句话说清这个岗位存在是为了解决什么问题 | "招一个资深前端" | "负责自有产品前端架构与交付节奏，把核心页面首屏时间压到 1.5 秒以内" |
| 半年关键产出 | 半年内要交付的具体结果，可验收 | "负责前端开发" | "完成 XX 系统重构；每两周交付一个可演示版本" |
| 硬性条件 | 不满足就基本做不成的事，3~5 条 | "3 年以上经验，35 岁以下，本科以上" | "能独立完成 X 类系统设计；有大流量场景经验（无经验可带）" |
| 排除项 | 明确不要的情况，可核验 | 隐含在老板心里 | "需每月出差驻场 2 周以上" |

### 1.1 硬性条件的写法

判断标准：**去掉这一条，岗位还能不能做成？** 能，就不是硬性条件，降级为加分项。

| 常见写法 | 实际问题 | 建议 |
|---|---|---|
| 3 年以上经验 | 经验年限与能力不必然对应 | 改为"能独立完成 X 类工作"；年限放加分项 |
| 某名校优先 | 与能力无因果关系，且排除供给 | 改为"有同等规模系统的实践经历" |
| 年龄区间 | 与岗位能力无关 | 删除 |
| 需带团队 X 人 | 若岗位本身是个人贡献岗 | 删除或改为"有带教、协同经历" |
| 熟悉某工具链 | 工具可学、能力难教 | 若与产出直接相关则保留，否则降级 |

### 1.2 排除项的合法边界

可写：
- 与岗位直接冲突的客观条件（出差频率、需长期驻场、必须持有某类证件、健康或安全岗位的法定要求）
- 明确无法提供的条件（如需自带设备但公司不提供）

不可写：
- 年龄、性别、婚育状况、户籍、地域、族裔、宗教信仰、是否为某一类学校毕业
- 与岗位无关的体型、健康状况、家庭状况
- 以"文化不合"名义列出的主观条件

判断方法：如果这项条件与"能不能干好这个岗位"没有可说明的因果关系，就不该出现在排除项里。

## 二、胜任力模型拆解表

### 2.1 项数分配

| 层级 | 数量 | 说明 |
|---|---|---|
| 通用能力 | 2 项 | 所有岗位都要考察 |
| 专业能力 | 1~2 项 | 本岗位特有，是招聘的主因 |
| 协作与价值观 | 1 项 | 必须写成可观察行为，否则删掉 |

合计 3~5 项。超过 5 项会导致面试轮次不够用、每项都只能浅聊。

### 2.2 每项胜任力的三件套

| 组成 | 写法 | 示例（"主动澄清需求"） |
|---|---|---|
| 项名 | 用行为命名，不用能力词 | 主动澄清模糊需求 |
| 行为描述 | 面试中可直接验证的行为 | "能主动指出需求中的矛盾或缺失信息，先确认再推进" |
| 考察方式 | 在哪个环节、怎么问 | 行为面主问题 + 一级至三级追问；看是否追问过时间线与角色边界 |

### 2.3 行为描述改写对照

| 不可用写法 | 问题 | 可用写法 |
|---|---|---|
| 沟通能力强 | 无法观察 | "能用对方能听懂的话解释复杂方案，遇到对方没听懂会换方式再讲一次" |
| 抗压能力好 | 无法证伪 | "讲一次你在时间明显不够时交付的经历，你砍掉了什么" |
| 有主人翁意识 | 抽象 | "遇到跨部门推不动的事，会自己先做一版出来再去谈" |
| 有格局 | 无法核验 | "讲一次你主动做超出自己职责范围的事，结果是什么" |
| 学习能力强 | 抽象 | "讲一次你在很短时间内上手陌生技术的过程，你是怎么学的" |
| 责任心强 | 抽象 | "讲一次你负责的事出了问题，你是怎么处理的" |
| 逻辑清晰 | 部分可观察 | "回答复杂问题时是否先澄清前提再给结论" |
| 有团队精神 | 抽象 | "讲一次你和同事意见不一致的争执，后来怎么收的" |

判断标准：**两个不同的面试官看完这段描述，能不能大致判断出行为算不算出现？** 不能，就还没写完。

### 2.4 胜任力模型的快速自检

- [ ] 每项都能在 45 分钟内被考察到至少一次
- [ ] 每项都有至少 1 个主问题，且追问层级已写好
- [ ] 没有无法证伪的形容词
- [ ] 项数不超过 5
- [ ] 每项都能对应到岗位画像中的某条使命或产出
- [ ] 各项之间没有明显重叠（避免同一件事被问两遍）

## 三、简历初筛四类标准

| 类别 | 定义 | 数量 | 判定方式 |
|---|---|---|---|
| 硬性条件 | 不满足即基本不可能做成 | 3~5 条 | 逐条打勾/打叉 |
| 加分项 | 满足则加权，不满足不排除 | 2~4 条 | 标注满足几条，用于加权比较 |
| 一票否决项 | 出现即排除，只放合规风险与硬性冲突 | 1~3 条 | 有则排除，无则继续 |
| 待澄清项 | 简历上看不出、要在面试中问的 | 写成问题清单 | 转入面试提纲 |

### 3.1 初筛记录模板

```
候选人：______  渠道：______  投递日期：______  筛选人：______

硬性条件
[ ] 1. ______  [ ] 2. ______  [ ] 3. ______
加分项：满足 ___ 项（列明：______）

一票否决项：无 / 有（说明：______）

待澄清项（转入面试）
1. ______
2. ______

结论：约 / 不约
理由（一句话）：______
```

### 3.2 初筛常见错误

| 错误 | 表现 | 后果 | 修法 |
|---|---|---|---|
| 标准来自偏好不是能力 | 用"某名校""大厂背景"做硬性 | 供给收窄时无人可招 | 改为能力与产出描述 |
| 加分项写成硬性 | 6 条以上硬性 | 合格候选人被卡掉 | 超过 5 条就往加分项移 |
| 不写理由 | 只打勾打叉 | 三个月后自己也说不清 | 每份留一句理由 |
| 口头筛选 | 电话里凭印象定 | 印象分污染后续环节 | 简历筛选书面化 |
| 一个人筛到底 | 渠道与标准混在一起 | 换渠道就要换标准 | 同一岗位固定标准，跨渠道一致 |
| 不留待澄清项 | 把"看不出"当作"没有" | 误排有潜力的人 | 单列待澄清项，转面试问 |

### 3.3 初筛的量化辅助（可选）

数据够用时可以引入，但**不能替代判断**：

| 指标 | 算法 | 参考意义 |
|---|---|---|
| 初筛通过率 | 初筛通过数 ÷ 投递数 | 过高说明标准偏松，过低说明硬性条件过严 |
| 渠道通过率差异 | 各渠道通过数 ÷ 各渠道投递数 | 差异大说明渠道人群与岗位不匹配 |
| 面试到场率 | 到场数 ÷ 邀约数 | 偏低先查邀约话术与流程长度 |
| 面试通过率 | 通过数 ÷ 面试数 | 显著高于同类岗位要警惕标准偏松 |

数据不足时不要硬算，先把记录做起来。

## 四、岗位画像 → 胜任力 → 面试 的贯通检查

| 检查项 | 通过标准 |
|---|---|
| 画像里的每条硬性条件都有对应的考察方式 | 是（在哪个环节问、怎么验） |
| 胜任力项都能追溯到画像中的使命或产出 | 是 |
| 待澄清项都已转成具体问题 | 是 |
| 每轮面试都有明确的主责面试官 | 是 |
| 决策权归属清楚 | 是（谁拍板写明） |
| 关键岗与可替代岗的流程强度不同 | 是 |

任何一项不通过，说明流程还是"凭感觉"的形态，只是套了表格。
