# 面试轮次分工、结构化题库与评分表设计

配套专家包：tingyun-recruiting-system（招聘流程与面试评价顾问）

本文件提供轮次矩阵、题库模板、追问结构与评分锚点示例。所有内容为一般性参考。

---

## 一、面试轮次分工矩阵

### 1.1 完整流程（关键岗）

| 轮次 | 目的 | 面试官 | 时长 | 产出 | 决策权 |
|---|---|---|---|---|---|
| 0. 简历初筛 | 基本条件与薪酬预期是否匹配 | 招聘负责人 | 书面 | 约/不约 + 理由 | 否（仅筛选） |
| 1. 电话初面 | 动机、沟通表达、薪资区间、到岗时间 | 招聘负责人 | 15~20 分钟 | 约/不约 + 待澄清项 | 否 |
| 2. 专业面 | 岗位核心能力 | 专业面试官 | 45~60 分钟 | 分项评分 + 事实记录 | 否（提供信息） |
| 3. 交叉面 / 协作面 | 协作方式、反馈接收、冲突处理 | 未来同事或平级 | 30~45 分钟 | 分项评分 + 事实记录 | 否（提供信息） |
| 4. 负责人面 | 长期投入意愿、对业务的理解、价值观匹配 | 老板或部门负责人 | 30~45 分钟 | 决定意见 | 是 |
| 5. 背景核查与入职前 | 履历核验、手续准备 | HR | — | 核查记录 | 否 |

### 1.2 分工三原则

1. **每轮只解决一个问题**：不要把所有题都堆给一个人。专业面就问专业，负责人面就问动机与长期投入。
2. **决策权与信息提供分开**：老板做决定轮，用人部门做专业轮。避免"用人的说不行、拍板的说好"这种僵局，也避免老板面试时凭印象拍板。
3. **评价独立、汇总在后**：面试官之间在面完前不讨论该候选人的表现，避免趋同；但评价必须各自写完再开会，顺序是"先各自写、后开会"。

### 1.3 面试官负荷估算

| 轮次 | 每位候选人的时间成本 | 说明 |
|---|---|---|
| 简历初筛 | 15~25 分钟 | 含记录 |
| 电话初面 | 15~20 分钟 | 含记录 |
| 专业面 | 45~60 分钟 + 30 分钟整理评分 | 整理时间常被低估 |
| 交叉面 | 30~45 分钟 + 20 分钟整理 | — |
| 负责人面 | 30~45 分钟 | — |
| 合计 | 约 3.5~4.5 小时 | 一个人负责一个岗位全部轮次时，按此估算招聘周期 |

一个岗位的完整流程通常跨 5~15 天。若业务方要求"一周内到岗"，必须砍轮次（见轻量流程参考），不能砍评价标准。

## 二、结构化题库模板

### 2.1 题库组织结构

按**胜任力项**分组，而不是按面试官分组。每组包含：主问题（必问，固定文本）+ 追问（1~3 级）+ 记录要点。

```
胜任力项：主动澄清模糊需求
主问题：请讲一次你主动发现需求方说得不清楚、并去确认的例子。当时是什么情况？
  一级追问：需求方起初怎么说的？你怎么发现不清楚的？
  二级追问：你具体怎么问的？对方怎么回答的？
  三级追问：确认之后你的方案有变化吗？如果没变，为什么？
记录要点：他是否识别出模糊点 / 追问方式 / 确认后才推进 / 是否说明了确认结果的用处
```

### 2.2 三级追问结构

| 层级 | 追问内容 | 目的 | 注意 |
|---|---|---|---|
| 一级 | 当时具体是什么情况？ | 还原场景 | 不要打断细节 |
| 二级 | 你具体负责哪部分？时间线是怎样的？ | 确认角色边界与真实参与度 | 关键区分"我"和"我们团队" |
| 三级 | 如果重来一次你会怎么改？为什么？ | 看反思与真实理解 | 答不上来不扣分，重点看他是否能诚实说"没想过" |

三级追问是区分"背题"与"真做过"的关键。只问一层，多数候选人会给准备过的答案。

### 2.3 主问题三条件

| 条件 | 含义 | 反例 | 正例 |
|---|---|---|---|
| 具体 | 指向过去真实发生的事 | "你觉得自己抗压吗" | "讲一次你在时间明显不够的情况下交付的经历" |
| 中立 | 不暗示期望答案 | "遇到困难你会不会放弃" | "讲一次你在项目里卡住时间较长的一次，后来怎么处理的" |
| 可核验 | 答案里有事实、时间、结果 | "介绍一下你做过的项目" | "挑一个你独立负责的模块，讲背景、你负责的部分、结果" |

### 2.4 现场任务（可选）

技术岗或需要实操的岗位可用，但要**事先定好评分口径**，否则现场表现无法比较。

| 任务类型 | 示例 | 评分口径要先写清 |
|---|---|---|
| 编码任务 | 实现一个带边界条件的函数 | 正确性、可读性、边界处理、提问习惯 |
| 方案拆解 | 给一个真实需求做技术与排期拆解 | 拆解顺序、优先级判断、风险识别 |
| 案例分析 | 一份业务数据，要求找出问题 | 口径意识、追问数据的习惯 |
| 现场改稿 | 给一段有问题的文案 | 修改理由是否讲得出 |

规则：给所有候选人**同一份材料**；限时相同；评分表上先写好观察项。

## 三、评分表与评价锚点

### 3.1 评分表结构

| 区块 | 内容 | 要求 |
|---|---|---|
| 基本信息 | 候选人、岗位、轮次、面试官、日期 | — |
| 事实记录区 | 候选人说的具体事实（时间、场景、动作、结果） | 只写事实，不写评价 |
| 分项评分 | 每项胜任力 1~4 档 + 锚点对应的具体证据 | 必须引用事实记录区 |
| 结论 | 达到岗位门槛 / 未达到 / 信息不足 | 用"达到门槛"表述，不用总分排序 |
| 待核实 | 记录里存疑、需下一轮确认的点 | 转给下一位面试官 |

### 3.2 四档锚点示例（以"主动澄清模糊需求"为例）

| 档位 | 锚点描述 |
|---|---|
| 4 | 能主动指出需求中的矛盾或缺失信息，提出具体的澄清问题，澄清后才推进；能说明澄清结果如何影响方案 |
| 3 | 需求模糊时会提问，但提问较浅（仅确认字面意思），确认后即推进 |
| 2 | 需求模糊时倾向按自己理解直接推进，被指出后才修正 |
| 1 | 未察觉需求存在模糊之处，按错误前提一路推进 |

### 3.3 锚点写法规则

| 规则 | 说明 |
|---|---|
| 用行为描述 | 写"做了什么"，不写"有多强" |
| 每档必须能被观察到 | 不能靠印象判断的描述要重写 |
| 4 档与 1 档要拉开 | 中间档写 2、3 档的分界（有的团队只有 3 档，也可，但分界要清楚） |
| 锚点来自实际录用者 | 把已入职同事的表现倒推成锚点，比凭空虚构更准 |
| 定期校准 | 每招 5~10 人后，回头看录用者的实际表现与当时评分是否一致 |

### 3.4 三个实施要点

1. **先写事实再写分数**。顺序颠倒会出现"先给个感觉分，再找理由凑"的合理化过程。
2. **不合并总分**。总分会掩盖"专业极强但协作不行"这类关键差异。比较时按"是否逐项达到门槛"看。
3. **记录与分数要对得上**。写出分数但引用不到事实，说明这个分数没有依据。

### 3.5 常见失效写法

| 写法 | 问题 | 改法 |
|---|---|---|
| "很好" | 无共同标准 | "能主动指出需求矛盾并追问到确认后才动手" |
| "比较强" | 程度副词，无锚点 | 明确行为 |
| "感觉不错" | 印象，非事实 | 只记录事实，分数延后填 |
| "有潜力" | 无法核验 | 写"在 X 环节表现低于门槛，但 Y 环节有亮点" |
| "沟通不太行" | 无具体所指 | "讲述项目时无法说清自己负责的部分" |

## 四、评价汇总规则

```
Step 1 每位面试官独立填写并提交评分表（含事实记录与分项评分）
Step 2 汇总人做横向比对：各面试官在每项上的打分差异
Step 3 差异大的项进入讨论；记录里有矛盾的项也进入讨论
Step 4 讨论只针对分歧项与待核实项，不重新评价全部项
Step 5 形成结论：达到门槛 / 未达到 / 信息不足（需加面）
Step 6 决策意见与评价记录分开存档，结论写明依据哪几条事实
```

补充规则：
- 面试官提交后才可见他人评价，减少趋同。
- 争议大且无法解决时，走"加一轮针对性面"而不是让老板拍脑袋决定。
- 拒绝理由要留存（对候选人有交代，也便于后续渠道与标准复盘）。

## 五、多面试官一致性校准

| 场景 | 做法 | 频率 |
|---|---|---|
| 新面试官上岗 | 用同一份虚构或真实候选人简历，全员独立打分后比对 | 上岗前一次 |
| 岗位标准调整 | 挑 2~3 名历史候选人重新评一遍 | 标准变更时 |
| 常规校准 | 挑近期候选人，看各面试官通过率差异 | 每季度或每 10 个候选人 |
| 分歧复盘 | 对结论不一致的候选人复盘原因 | 每次出现即做 |

通过率横向差异的解读：某位面试官通过率显著高于其他人，通常意味着标准偏松，而不是他面得更好。差异过大时优先校准锚点与题库执行度，而不是先换人。

## 六、结构化流程的落地阻力与应对

| 阻力 | 表现 | 应对 |
|---|---|---|
| 面试官嫌麻烦 | 不填评分表、口头汇报 | 把评分表做短（一张 A4）、现场填完提交 |
| 题库不熟 | 临场自由发挥 | 每轮开始前把本轮主问题发给面试官，不临场出题 |
| 老板要走捷径 | 只面一轮就拍板 | 明确关键岗的轮次下限约定，例外要留下决策记录 |
| 岗位本身没定义清 | 画像改来改去 | 先冻结画像版本，变更走记录，面试期间不改 |
| 招人太急 | 跳过结构化 | 允许砍轮次，不允许砍评价标准与记录 |
