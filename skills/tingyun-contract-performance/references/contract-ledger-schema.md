# 合同台账精简字段集与提醒规则

> 用于合同签订之后的履约过程管理。本文是流程与清单辅助，不构成法律专业意见，需人工复核。

## 一、为什么大多数合同台账会废掉

三个通病：

1. **当成档案柜**：字段堆到 40 多列，没人每周更新，三个月后全是过期数据；
2. **字段不触发动作**：记了"合同金额"但没记"这笔钱什么时候到账、到期没到找谁"，台账不能提醒任何人；
3. **只记外部动作、不记内部动作**：只记"应付款"不记"我方什么时候提交交付物"，结果发现是我方卡住了。

**判据**：一个字段如果不能回答"到期没到该谁做什么"，就不进台账。

## 二、精简可执行字段集（12 项）

### A. 主体与标识（4 项）
| 字段 | 填法要点 | 常见错 |
|---|---|---|
| 合同编号 | 用公司统一编号规则（如年份-序号-类型码），后续所有变更单、验收单、发票都引用它 | 一事一单号，后续单据挂不上，找不到原件 |
| 对方名称 | 写全称+统一社会信用代码 | 只写简称或品牌名，对不上主体，争议时无法确认是谁 |
| 我方主体 | 与实际签章主体一致 | 实际是分公司签，台账写总公司，付款主体对不上 |
| 合同金额 | 注明币种、含税/不含税口径 | 只记一个数字，对账时双方口径不同 |

### B. 时间轴（3 项）
| 字段 | 填法要点 | 常见错 |
|---|---|---|
| 签署日期 | 实际签章完成日，不是意向书日 | 用报价单日期，提醒整体提前 |
| 起止日期 | 履约开始日与到期日分开填 | 只填一个"合同期"，中间节点算不出来 |
| 付款条件摘要 | 简化成"验收后 X 日内付 Y 元"这种可判断的句子 | 抄条款原文，关键条件埋在长句里没法判断 |

### C. 节点（3 项）
| 字段 | 填法要点 |
|---|---|
| 付款节点 | 拆成行：序号 / 金额 / 触发条件 / 约定支付日 / 状态 |
| 交付节点 | 拆成行：序号 / 交付内容 / 我方提交日 / 对方确认期限 / 状态 |
| 验收节点 | 是否需要验收、验收单名称、逾期未验收如何处理 |

### D. 状态与责任（2 项）
| 字段 | 填法要点 |
|---|---|
| 变更记录位置 | 指向存放变更单/补充协议的目录或编号区间 |
| 责任人与提醒提前量 | 每个节点挂一个姓名 + 提前几天提醒 |

> 合计 12 项核心字段。超过 20 列的台账，实际维护率会掉到无法持续。

## 三、节点状态机（统一用这套，别自定义）

```
待启动 → 进行中 → 待对方确认 → 已确认 → 已结算
              ↓
            已逾期（升级处理）
              ↓
            已变更（挂到变更分支）
```

状态定义与推进责任人：

| 状态 | 判定条件 | 谁推进 | 卡住超过多久升级 |
|---|---|---|---|
| 待启动 | 还没到触发条件 | 节点责任人 | 到期前 3 天未动 → 提醒责任人 |
| 进行中 | 我方正在做 | 节点责任人 | 超过计划工时 1.5 倍 → 报项目负责人 |
| 待对方确认 | 已提交，等对方签收 | 商务/对接人 | 超过对方确认期限 → 发书面确认函 |
| 已确认 | 对方书面签收/验收 | — | — |
| 已结算 | 款项到账并核销 | 财务 | 到账后 3 个工作日未核销 → 财务核对 |
| 已逾期 | 超过约定日期仍未推进 | 负责人 | 立即列入周会清单 |
| 已变更 | 被变更单替代 | 变更经办人 | 变更单未签署 → 该节点不得计入履约完成 |

**关键规则**：`已变更` 状态只有在变更单双方签署后才成立。仅有一方签字或仅有即时通讯/邮件确认的，进"待对方确认"。

## 四、提醒分级规则（提前量 + 升级）

| 提醒级别 | 触发时点 | 动作 | 通知对象 |
|---|---|---|---|
| L1 预告 | 到期前 14 天（长期节点）/ 7 天（短期节点） | 系统或表格标记，责任人自查 | 节点责任人 |
| L2 提醒 | 到期前 7 天 / 3 天 | 主动发函或电话给对接人 | 责任人 + 商务 |
| L3 预警 | 到期前 2 天 / 到期当日 | 升级并准备书面确认函模板 | 项目负责人 |
| L4 逾期 | 超过约定日期 | 形成逾期清单 + 合同条款对照表 | 负责人 + 管理层 |

### 升级时的动作模板（可直接用）
> "关于《合同编号》项下第 X 号节点（约定日期：____），截至 ____ 尚未收到贵方确认。按合同第 __ 条约定，我方已于 ____ 完成提交（附件：____）。现再次函告，请于 ____ 前予以书面确认，逾期我方将按合同第 __ 条处理。"

要点：写明合同条款号、写明我方已完成的事实与日期、给出明确回复期限、说明逾期后果（引条款，不夸大）。**不含威胁性表述，不使用"必然""一定"等断言式措辞。**

## 五、每月台账巡检 8 问

1. 本月到期的节点有哪几个？责任人在哪？
2. 有没有节点已过约定日期但仍标"进行中"？
3. 有没有我方已提交但对方未确认超过约定确认期的节点？
4. 本月发生的变更全部书面化了吗？有没有仍停留在聊天记录的？
5. 哪些节点已确认但未开票？哪些已开票但未到账？
6. 合同里有无"到期自动顺延""未提出异议视为认可"这类条款？顺延条件是否满足？
7. 未来 30 天内有合同到期或质保期届满吗？决策人定了吗？
8. 台账里有没有字段超过 60 天没更新过的？那说明台账已经失效了。

## 六、台账常见的 3 个设计错误

| 错误 | 后果 | 修法 |
|---|---|---|
| 只记"待收金额"，不记"已开票/在途/已到账" | 对账时看不出钱卡在哪一环 | 拆成待收、已开票在途、已到账三列 |
| 用一列"状态"混装节点状态和合同状态 | 无法筛选，无法批量提醒 | 节点状态归节点表，合同状态归主表 |
| 把合同全文粘贴进表格备注列 | 表格没法用，退化成垃圾桶 | 只存路径或编号，文本另存归档 |
