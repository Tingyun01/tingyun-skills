# 云开发架构经验（微信云开发 / TCB）

> 独立开发者首选架构：原生小程序 + 微信云开发。本文沉淀从多个上线项目中得出的架构决策与避坑结论。

## 1. 选型结论

| 方案 | 适用 | 结论 |
|---|---|---|
| 微信云开发（TCB） | 独立开发者、MVP、中小流量 | **默认选择**：免运维、免域名备案、云函数免鉴权调开放接口、自带存储 CDN |
| 自建后端 | 已有服务器、复杂业务、强定制 | 成本高：需域名备案、HTTPS 证书、运维、防刷 |
| Taro/uni-app 跨端 | 需同时出多端 | 跨端框架调试成本高，纯微信场景用原生更稳 |

云开发注意：
- 选用云开发**不免除小程序 ICP 备案**。
- 云数据库按量付费，注意用量告警；免费额度适合 MVP，放量前看账单。

## 2. 数据模型设计

- **主键策略：用 OPENID 作为用户数据的主键**。教训：用设备号/随机 ID 做云端备份 key，用户换设备或清缓存后数据"丢失"。`cloud.getWXContext().OPENID` 在云函数中稳定获取。
- 集合划分按"读模式"而非"写模式"：高频读的配置、内容类数据单独成集合，便于一次性拉取缓存。
- 本地优先（local-first）：可离线使用的数据（如用户设置、离线内容）先写本地 Storage，异步同步云端；网络差时体验不崩。

## 3. 图片加载优化（高频事故区）

**症状**：云存储图片不显示 / 移动端加载缓慢。

排查顺序：
1. **fileID 路径正确性**：格式为 `cloud://<env-id>.<bucket>/path/file.jpg`，逐字符核对（env 后缀、目录大小写、扩展名）。最常见错误是手拼路径多了/少了层级。
2. **权限**：云存储权限默认"仅创建者可读"——展示型图片必须改为"所有用户可读"，或走临时 URL（`getTempFileURL`）。
3. **临时 URL 缓存**：`getTempFileURL` 返回的链接有时效，不要长期缓存；列表页批量换取一次。
4. **体积**：上传前压缩。经验值：展示图压至 **200KB 内 JPG**（长边 ≤2000px），首屏可再压。大图原图直接上传是"加载缓慢"的头号原因。
5. **首屏渲染**：图片加 `lazy-load`、固定宽高比占位（避免布局抖动）、关键路径图片用 CDN/云存储而非 base64 内联大图。

## 4. 云函数规范

- 一个云函数做一件事；高频调用的接口合并成"聚合函数"减少冷启动次数，但不要把所有逻辑塞一个函数（部署粒度与超时都受影响）。
- 所有云函数顶层 try/catch + 统一返回结构 `{ ok, data, msg }`，前端好做兜底。
- 涉敏感操作（写库、删数据）在云函数端校验 OPENID 权限，前端校验只是体验优化不是安全边界。

## 5. 内容安全

- 所有 UGC（昵称、留言、问卷答案）入库前过 `security.msgSecCheck`；图片过 `security.imgSecCheck`。
- 宽松审核策略可以：硬拦明显违规，模糊内容放行但在界面展示用户免责声明（"内容由用户发布，不代表本平台立场"）。
- 机制必须在——审核被拒的头号原因之一就是"UGC 无审核机制"。

## 6. 性能与体积

- 主包 ≤2MB 硬线（分包上限另计）：图片资源一律放云存储/CDN，不放包内。
- 分包策略：按 Tab 页拆主包，低频功能（设置、关于、帮助）拆分包。
- `setData` 传大对象是卡顿主因：只传渲染所需字段，长列表用分页 + 骨架屏。

## 7. 内测开关模式（protect-live 模式）

实验性功能的推荐做法：

```js
// app.js 全局配置
globalData: {
  surveyBetaMode: false  // 实验功能总开关
}
// 页面渲染入口
wx.getStorageSync('_beta_user') && this.setData({ showSurvey: app.globalData.surveyBetaMode })
```

- 开关默认关闭，线上用户零感知；给内测名单（按 OPENID 白名单）打开。
- 好处：新功能可以随版本提审（或隐藏不提审），出问题关开关即回滚，无需紧急发版。
