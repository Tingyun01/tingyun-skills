# 真实驳回案例库（平台审核原话实录）

> **本文件的每一句驳回原话，都是真实提交—驳回—整改回路里平台审核员写的**，
> 来自三个实际运营的小程序（爱入眠 / 押金卫士 / 校园成长工具箱，含口袋秘书前身）。
> 公开文档与教程里查不到这些原话与背后的机制。诊断时优先用本文件对照。

---

## 0. 怎么用这份文件

1. 先让用户**逐字复制微信给的驳回通知**（不要转述）。
2. 在下面 §1 找**语义最接近**的一条，看它的「表面理由 → 真实原因 → 修复动作」。
3. **注意 §5 的三条元规则**——本库一半以上的坑不在"改什么"，而在"改了几层"和"谁在审你"。

## 1. 平台驳回原话清单（15 条，按主题分组）

### 组一：功能完整性 —— 「点击无响应」

#### R1｜协议功能点击无响应
> 失败原因：小程序服务【协议】功能点击无响应，无法体验完整流程。

- **表面**：协议功能坏了。
- **真实原因**：审核员不是从首页点进来的，是从**后台功能清单/扫码深链直达协议页**。此时页面栈长度为 1，`wx.navigateBack()` **静默失败**（不报错、不跳转、用户只看到"点了没反应"）。本地从首页点进去自测 100% 复现不了。
- **修复动作**：所有"进入即用"的单页功能（协议页、授权页、隐私弹窗、付费页、错误页）都加兜底：
  ```js
  const pages = getCurrentPages();
  if (pages.length > 1) wx.navigateBack();
  else wx.switchTab({ url: '/pages/index/index' });   // 栈深为 1 时改用 switchTab
  ```
- **预防**：提审前**用后台功能清单里的路径逐个扫码直达**测一遍，不要只从首页走。
- **来源**：校园工具箱 `changelog/2026-08-17-审核驳回协议按钮无响应修复.md`

#### R2｜隐私政策功能点击无响应
> 小程序服务【隐私政策】功能点击无响应，无法体验完整流程

- **表面**：同上。
- **真实原因（两层）**：
  1. 首页协议弹窗（`showConsent`）里的《用户协议》《隐私政策》是**纯文本，没有绑定任何点击事件**——审核员根本点不动。
  2. 绑上事件后仍"点不动"：弹窗内链接用了 `bindtap`，事件**冒泡**到外层 checkbox 的 tap 处理器，勾选状态被误触又同时触发跳转，表现还是"点了没反应"。
- **修复动作**：弹窗内链接一律用 **`catchtap`**（阻止冒泡），并把勾选框的 tap 与链接的 tap **完全隔离**；checkbox 热区从 32rpx 放大到 44rpx（小于 44rpx 审核员点不准也会被判"无响应"）。
- **来源**：校园工具箱 `changelog/2026-08-21-审核修复-隐私政策弹窗链接可点击.md`

#### R3｜登录环节强制弹窗（**一手后台页面截图原文**）
> 审核失败原因 小程序登录环节，需为用户提供显著有效的可取消/拒绝或返回按钮，不得反复弹窗或强制用户进行登录并提供体验。
> 修改指引 关于"收集用户手机号授权登录弹窗"侧解析和整改建议

- **真实原因**：登录弹窗没有可用的"拒绝"路径，审核员点不掉。
- **修复动作**：①提供显著可见的「暂不登录 / 游客进入」按钮；②首次弹、拒绝后**不再自动弹**；③拒绝后必须有**可用的降级路径**（否则审核员点拒绝 → 页面空白 → 追加一条"功能不完整"）。
- **来源**：校园工具箱 `changelog/2026-09-07-登录环节合规整改.md` + **微信后台「版本审核修改指引」页面截图**（本地实文件 `dist/_codebuddy_images/6fb345d6_mq-1788764108797-betqnx_000.png`，可直接读图对证）

> ⭐ **元规则（本条最值钱的部分）**：微信的驳回通知不只有"失败原因"字段，还有独立的**"修改指引"字段**——它会**指向具体公告 + 具体解析文档**（本例是"关于收集用户手机号授权登录弹窗侧解析和整改建议"）。
> **读驳回通知时不要只看失败原因，"修改指引"字段往往藏着比失败原因更精确的整改指向。**

### 组二：内容安全 —— 接口没接

#### R4｜内容安全验证失败
> 你的小程序【头像】功能在进行内容安全验证时，存在信息安全风险，请尽快完善内容安全机制（错误码 -1，参考链接：…/security.msgSecCheck.html）

- **真实原因**：用户上传的头像没接 `msgSecCheck`/`imgSecCheck`，微信在审核时对上传内容做安全验证直接判风险。
- **修复动作**（UGC 三件套，缺一不可）：
  1. 发布前接 `msgSecCheck`（文本）/ `imgSecCheck`（图片）做校验；
  2. 每条 UGC 给举报入口；
  3. 用户协议写明"用户对发布内容负全责"。
- **⚠️ 反噬警告**：本项目后来做过一次"零成本架构改造"，把云端 `msgSecCheck/imgSecCheck` **降级成本地敏感词表**，图片检查直接 `pass:true` 放行（`utils/content-security.js`）。**合规能力被优化反噬掉了**——fail-open 等于绕过审核。降本改造必须同时评估合规影响。
- **来源**：口袋秘书 `changelog/2026-07-13-内容安全API接入-审核修复.md`

### 组三：虚拟支付 / 付费能力

#### R5｜虚拟支付未接入官方能力（v3.0.0）
> 小程序内售卖虚拟服务/道具未接入官方「小程序虚拟支付」能力

#### R6｜虚拟支付 v3.0.1 二次被拒（换皮后仍被驳）
> 失败原因：小程序服务内提供虚拟产品/虚拟商品购买服务，需接入官方「小程序虚拟支付」能力。

- **R6 是本库最有价值的一条**：代码侧**已经完全改完**（`wx.requestVirtualPayment` 已接入、确认无普通支付残留），仍被**同一条理由**驳回。
- **真实原因**：微信审的是「**后台虚拟支付能力有没有开通**」，不是「代码有没有改」。后台 OfferID / 能力没配，代码写得再对也没用。
- **修复动作**：代码改完 → **去后台开通虚拟支付能力并拿到 OfferID** → 再提审。同时核对 iOS 端是否需要差异���（iOS 禁止虚拟支付）。
- **来源**：口袋秘书 `.codebuddy/memory/2026-07-06.md`
- **措辞变体**：茅山趣测同一次通知里写的是「失败原因2：虚拟产品购买服务 → 必须接入官方"小程序虚拟支付"能力」——**同一规则两种措辞**。
- **⚠️ 事实更正**：微信官方虚拟支付**支持 iOS**（驳回通知里直接链接了 iOS 文档）。此前"iOS 不支持虚拟支付"的说法**是过时信息，不要再沿用**。
- **个体户能不能用虚拟支付？——能**（口袋秘书为证）。真正的三个卡点是：①**后台支付开关未开**（`enabled` 默认 false）②**iOS 端需按官方能力接入** ③**服务类目必须匹配**（如文娱-文化馆 / 教育-在线课程），类目不匹配照样被拒。

### 组四：玄学 / 算命类目

#### R7｜涉及算卜算运势、算命、付费取名
> 涉及算卜算运势、算命、付费取名

- **首次提审驳回**。
#### R8｜二审因同一原因再次被驳
> 用户提交后又被驳回（仍是"算卜算运势/算命/付费取名"）

- **真实原因**：整改时**只改了文字表述，功能没删**。36 签 + 三问三答 + 点蚊香 + 搓手 + 选老师 + 摇箴言这套"算命仪式"UI 还在。
- **修复动作（正确姿势）**：**整类清零，而不是逐条改文案**。该项目的实际做法是——删掉 148 个 view 的算命仪式浮层、18 个算命函数、31 行敏感 data 字段，把 36 签数据重写成"配图清单"。**把功能本身移除，驳回理由自然消失**，而不是去找审核员爱听的说法。
- **⚠️ 二次驳回的教训**：改了表述没改功能，机器不会给第二次机会。
- **来源**：押金卫士 `.codebuddy/memory/MEMORY.md:88-89`
- **跨项目互证**：茅山趣测（押金卫士前身）v3.0.0 首次提审**独立复现**同一条驳回，原话措辞为「失败原因1：涉及算命、算运势、付费取名等内容 → 平台未允许，必须移除」——说明**算命类是跨项目系统性雷区，不是偶发**。
- **⚠️ 措辞会变**：同一类驳回在不同项目的通知里措辞不同（"算卜算运势、算命、付费取名" vs "涉及算命、算运势、付费取名"），**诊断要按语义匹配，不能精确匹配原句**。

### 组五：类目与主体资质

#### R9｜类目不符（保险展业内容过不了社交类目）
- **真实原因**：产品做的是保险展业话术训练，触及社交/营销类目的资质要求；竞品走的是「工具 > 办公」绕开敏感类目。
- **修复动作**：**类目"向下兼容"**——不新增教育类目，把功能挂到已有类目下（信息咨询 / 深度合成AI / 笔记）。类目是"能力上限"而不是"功能标签"。
- **来源**：校园工具箱 `changelog/2026-08-09-停云新生指南备案变更填报文案.md`

#### R10｜有偿信息服务触及资质红线（**结论要精确，别搞混**）
- **先说清楚三件容易被搞混的事**：

  | 问题 | 正确结论 | 依据 |
  |---|---|---|
  | 社交类目能申请吗？ | **能**。个体户可申请「社交-社区/论坛」，需《非经营性互联网信息服务备案核准》（ICP 备案号），周期 7-15 工作日。**"社交类目不可行"是过度断言** | 微信官方社区回复 + 官方《小程序备案服务内容选择指引》 |
  | 保险/金融能卖吗？ | **不能**。个体户和个人都不允许做保险/金融类销售——**业务本身被禁止**，不是资质不够。微信「金融业-保险」类目要保险机构/中介的《经营保险业务许可证》等 8 类证照，个体户拿不到 | 微信官方《小程序开放的服务类目》 |
  | 个体户能办增值电信业务经营许可证（ICP 许可证）吗？ | **不能**。①《电信业务经营许可管理办法》第六条：经营者必须为**依法设立的公司**（个体户不是公司）②注册资本最低限额 100 万 | 广东省通信管理局 2025 官方问答 |

- **⚠️ 但"小程序需要 ICP 许可证"本身就是个常见误解**：工信部《常见问题解答清单》明确——**企业依托微信、支付宝等互联网平台的小程序、公众号、视频号、H5 网站、线上店铺等形式经营业务，且无其他独立运营平台的，无需取得《增值电信业务经营许可证》**。
  微信真正要的是**《非经营性互联网信息服务备案核准》（ICP 备案号）**——这是**免费**备案，主体不限，个人也能备案。
- **所以个体户的真实生存带**：**工具类 + 教育/信息咨询类 + 自有内容 + 广告/激励变现**。只有做"平台型"业务（多商家入驻、撮合交易、EDI）才需要 EDI 证（个体户不可办）。
- **应对**：①产品改免费 + 靠激励视频广告变现（绕开"有偿信息服务"）；②或升级主体为有限责任公司。
- **来源**：校园工具箱 `changelog/2026-08-11-法律合规体检修复.md`（人工复核清单 P0-3）+ 广东省通信管理局 2025 官方问答 + 工信部《常见问题解答清单》

#### R11｜后台类目/服务类目/备案/隐私保护指引未完成配置
- **真实原因**：代码侧整改完成，但**后台的类目、服务类目、备案、隐私保护指引勾选**还没做完。
- **结论**：**代码改对 ≠ 过审**。后台配置是独立审核项。
- **来源**：口袋秘书 `.codebuddy/memory/2026-07-06.md:12-19`

#### R12｜简称不合规（字符数超限 / 跳字截取）
- **真实原因（两条独立规则）**：
  1. 微信简称限 **4–10 字符**；
  2. **简称必须从全称里"连续顺序截取"，不能跳字**。例：全称"押金卫士拍照存证"里截"押金存证"是跳字的，不合规。
- **修复动作**：显式写出算式（`简称 = "X" + "Y" + "Z"，共 N 字`）并由另一方复核。**AI 自审最常在这里出错——自己数一遍觉得没超，其实超了。**
- **⚠️ 别怕次数**：改名是**每年 2 次**机会（不是 1 次）；**被驳回不计入次数，只有审核通过、名称正式生效才计** → **不要因为怕次数就不提报**。
- **来源**：校园工具箱 `changelog/2026-08-29-简称合规性修正-避坑工具箱.md` + `d-WorkBuddy-2026-08-23-10-27-47` 会话 L314/L444

### 组六：路由与资源命名（最反直觉的一类）

#### R13｜机器审核按路由名归类功能
- **真实事件**：同一上午自查判定"完全合规"，2 小时后被改判"机器审核会直接斩杀"。
- **真实原因**：路由/文件夹名叫 `shop` → **被机器审核归类为电商** → 斩杀。整改方式是**把文件夹改名** `shop` → `material-hub`（资料中心），而不是写免责声明。
- **同类**：云存储图片批量改名（`茅山符箓.jpg`→`茅山印记.jpg`、`道士画符.jpg`→`道人习艺.jpg`）——**连资源文件名都是审核输入**。
- **来源**：校园工具箱 `changelog/2026-08-11-v1.4-六AI联合诊断全面升级.md`

#### R14｜深度合成类目 + AI 生成标识（**AI 功能类小程序必看**）
> 审核失败原因 你好，你的小程序涉及提供文本深度合成技术（如：AI 问答）等相关服务，请补充选择：深度合成-AI 问答类目，并在 AI 生成页面增加显著说明"AI 生成、人工智能生成"或同等含义字样。

- **平台驳回通知的完整结构**（这条让我们看清了微信后台驳回页长什么样）：
  ```
  版本审核修改指引
  失败原因1
  审核失败原因  [上面那段]
  截图
  修改指引  关于"人工智能生成合成内容需增加显著标识"公告
  是否接受修改指引
    我接受
    我不接受，存在误判
    我不理解以上内容
  ```
  ⚠️ **"我不接受，存在误判"就是申诉入口**——所以看到驳回先别急着改，先判断是不是误判。
- **真实原因**：用了 AI 能力但没申报深度合成类目，也没在 AI 生成页面加显著标识。
- **修复动作**：①补充选择「深度合成-AI 问答」类目；②AI 生成页面加显著"AI 生成 / 人工智能生成"字样。
- **⭐ 关键情报——类目资质成本由技术实现决定**：补深度合成类目会连带要求「算法备案截图」+「合作协议」（当调用第三方 AI API 时）。但核查代码确认是**纯本地合成、零网络请求**（如 Web Audio API 本地生成音频）时，**可豁免**——回复审核员："该功能为纯本地程序化合成，不调用任何第三方 API 或云服务，无需算法备案或外部合作协议。"
- **来源**：爱入眠 v2.0.1，`d-WorkBuddy-2026-06-12-12-58-04` 会话 L157（老袁原样粘贴微信后台页面文本）

#### R15｜名称被判"通用服务词"
- **真实原因**：微信把名称里的**功能词**（如"拍照存证"，就像"外卖""打车""记账"一样）当"通用服务描述"审，于是整个名字被当成"通用功能描述"给拒了。
- **修复动作**：给功能词**加场景限定或品牌词**，让名字不再像一个通用功能分类。
- **来源**：押金卫士，`d-WorkBuddy-2026-08-23-10-27-47` 会话 L453

## 2. 表面理由 → 真实原因 速查表

| 平台原话关键词 | 90% 的真实原因 |
|---|---|
| 点击无响应 / 无法体验完整流程 | 审核员深链直达导致页面栈=1，`navigateBack` 静默失败；或事件用 `bindtap` 冒泡；或点击热区 < 44rpx |
| 内容安全验证存在风险 | 用户上传内容未接 `msgSecCheck`/`imgSecCheck` |
| 需接入官方虚拟支付能力 | 后台虚拟支付能力/OfferID **没开通**（代码改没用） |
| 涉及算命/算运势/占卜 | 功能本身还在，只改文字没用；且"仪式感 UI"本身也是信号 |
| 请选择正确的服务类目 | 类目天花板（主体资质决定上限）；应向下兼容而非硬闯 |
| 名称不符合规范 | 字符数超限（4–10 字符）；或含他人商标/保留词 |
| 存在诱导分享 | 强制分享话术；或分享是唯一入口（无替代路径） |
| 登录不合理 | 强制登录/无取消路径/拒绝后无降级 |
| 未配置隐私保护指引 | 代码调了敏感接口但后台没勾；或缺 `__usePrivacyCheck__` 三件套 |
| 存在信息安全风险 | 敏感表述残留（含**资源文件名**、路由名）；或"仪式感 UI" |
| 涉及提供文本深度合成技术（AI 问答） | 用了 AI 能力但没申报深度合成类目、没加"AI 生成"显著标识 |
| 名称被判通用服务词 | 名字里的功能词（拍照存证/记账/打车）被当"通用功能描述"审 |
| 简称不合规 | 超 4-10 字符；或从全称里**跳字截取** |

## 3. 整改必须同时做的五层（漏一层必被二次驳回）

这是从 R7/R8（改了文字没改功能）、R13（只改文案没改路由名）、R2（只绑事件没防冒泡）三次失败里总结出来的：

| 层 | 具体内容 |
|---|---|
| ① 功能页文案 | 页面上的文字表述 |
| ② 界面文案 | 按钮、提示、空状态、Toast |
| ③ 配置文件 | `app.json`（页面路由、tabBar、`__usePrivacyCheck__`）、`project.config.json`（`packOptions.ignore`） |
| ④ 资源文件名 | 图片/音频/云存储对象的文件名，**含英文路由目录名** |
| ⑤ 死代码与上传包 | 上传包里包含 README、开发脚本、测试数据——**它们也是审核语料**，用 `packOptions.ignore` 瘦身 |

**只有把五层都改完，敏感词密度才真的降下来。**

### 3.5.2 两个必须分清的"ICP"

| 名称 | 谁要 | 主体要求 | 费用 | 周期 |
|---|---|---|---|---|
| **ICP 备案号**（非经营性互联网信息服务备案核准） | **微信小程序备案**要的 | **个人/个体户/企业都行** | 免费 | 1-4 周 |
| **ICP 许可证**（增值电信业务经营许可证） | 平台型业务（多商家入驻、撮合交易）要的 | **必须是公司 + 注册资本≥100万** | 代办费 | 1-3 月 |

⚠️ **常见误解**："做小程序要办 ICP 许可证" —— **不对**。
工信部《常见问题解答清单》原文：**企业依托微信、支付宝等互联网平台的小程序、公众号、视频号、H5 网站、线上店铺等形式经营业务，且无其他独立运营平台的，无需取得《增值电信业务经营许可证》**。

### 3.5.3 一句话结论

**个体户的生存带 = 工具类 + 教育/信息咨询类 + 自有内容 + 广告/激励变现。**
要做"平台型"业务 → 必须升级主体为有限责任公司。

### 3.5.4 但要留神：证照可行 ≠ 平台会给

- **证照层面**：你有营业执照 → 类目资质可能达标
- **平台层面**：微信还看**产品实际功能**、**类目气质**、**内容**是否与类目匹配
- **"经营范围里有" ≠ "平台给你开这个类目"**（微信小店/抖音教育类目是定向邀约制）
- **"内容本身敏感" ≠ "换个类目就能过"**（保险/金融是业务红线，类目救不了）

## 4. 审核员行为档案（最容易被忽略的一节）

审核员**不是普通用户**，他是一个恶意测试者：

- 走**深链/扫码直达**，不从首页走 → 页面栈天然为 1
- 会主动点「拒绝授权」试探 → 必须有降级路径
- 会点最角落的链接 → 链接热区必须 ≥44rpx
- 会在弹窗里乱点 → 事件冒泡会误触
- 会用手机截图里的路径复现你后台配置的功能 → **后台配了就能被点到，配漏了不会**
- 会跑**第二次**（复审），并且会**引用同一个原因**

结论：**本地自测通过 ≠ 审核能通过**。提审前要按"审核员的路径 + 审核员的恶意操作"各走一遍。

## 5. 三条元规则

### 5.1 机器审核看的是「页面功能」，不是你的文案
路由名、文件夹名、资源文件名 = 你对审核系统的**功能声明**。改一个文件夹名，胜过写十段免责声明。

### 5.2 整改要"整类清零"，不是"逐条改文案"
审核是分类判定的。你改的那一条大概率不是被判的那一类。**全局排查同签名内容**是硬要求。

### 5.3 证据链要自己建，别靠转述
本项目 39 张图**没有一张是审核截图**，全是文字转述；最后一次驳回后**没有任何结果回填**——导致无法确认最终是否过审。
**建议的归档规范**：每次提审前存 ①提审版本号 ②后台配置截图 ③自检表 ④提审时间；驳回后存 ⑤驳回原话原文+截图 ⑥整改 diff ⑦重提时间 ⑧过审通知。缺一项，下一次就说不清自己改没改对。
