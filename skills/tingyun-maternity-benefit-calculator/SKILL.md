# 生育津贴待遇测算与申领核对助手

## 一、这个技能解决什么问题

生育津贴是**当地政府发的钱，不是单位发的钱**。但大多数人头一次去算它的时候，会遇到这四件事：

1. **算错基数** —— 以为按自己月工资算。官方口径绝大多数属地是按**"参保人所在用人单位上年度职工月平均工资"**算。防城港官方举的原例：参保女职工本人月工资 4500 元，但其单位上年度全体职工月平均缴费工资为 5000 元，津贴就按 **5000 元**计算，不按 4500 元。单位整体压低缴费基数，所有女职工一起吃亏。
2. **算错天数** —— 只知道"产假 98 天"。实际是 **98 天国家基础 + 地方奖励假 + 难产加假 + 多胞胎加假**。北京 128 天、宁德 128 天、佛山 128 天、防城港一孩二孩 128 天三孩 158 天。**而且地方奖励假期间通常由单位发工资、不享受津贴**——这是最容易算混的一格。
3. **算漏了"差额由单位补足"** —— 北京、上海、佛山都明文规定：津贴低于本人产假工资标准的，**差额部分由用人单位补足**。北京 12348 官方答复的原例：应得 73733 元、实发 32000 元，**差额 41733 元**。这一条几乎没人主动去主张。
4. **算漏了全国统一的那几笔** —— 育儿补贴每孩每年 3600 元至满 3 周岁、婴幼儿个税每月抵扣 2000 元、生育医疗费用待遇（与津贴**并列**，不是二选一）。这些和属地津贴是两套并行口径，漏报就是白丢钱。

**所以真正的问题不是"政策在哪查"，是"官方给了公式，但没告诉你该填哪个数、哪几格最容易填错、填错了少拿多少"。**

本技能做的事：**把口径拆成三段 → 分别标明依据 → 算出应发金额 → 自动比对出差额 → 输出可打印的核对单。**

## 二、适用与不适用

**适用：**
- 参保女职工（含灵活就业参保人员）核算自己或配偶的生育津贴
- HR、工会专员批量核对本单位的生育津贴申报口径
- 已经拿到津贴但怀疑被少发的主体，做差额自查
- 准备生育、想提前知道自己能拿多少、该问单位什么的人
- 产假结束后发现单位只发了部分工资，追问差额怎么算

**不适用：**
- ❌ **不做资格认定**。能不能领、生不生得出，参保地经办机构说了算
- ❌ **不承诺金额**。本技能给的是"按已采集的属地公开口径算出来的数"，政策一变就要重算
- ❌ **不做仲裁/诉讼代理**，不出具法律意见书
- ❌ **不代办任何手续**（不代填表格、不代提交、不代跑窗口）
- ❌ **不替代属地最新的政策文件**。已采集 7 个属地口径，其余一律标〔待补〕
- ❌ **不处理生育医疗费用的具体报销比例核定**（各地起付线、封顶线、个人自付处理差异极大，本技能只给核对动作）

**这个技能的定位是"算清楚 + 问对人"，不是"办成事"。** 用了它能少拿钱和不会算钱之间，是有差别的。

## 三、怎么用（三个动作）

### 动作一：把信息填进去

```json
{
  "region": "北京市",
  "identity": "在职职工",
  "scenario": "难产顺产",
  "base_wage": 14000,
  "own_wage": 14000,
  "contribution_months": 12,
  "social_avg_monthly_wage": 12000,
  "employer_paid_wage": 8000,
  "received_allowance": 32000
}
```

| 字段 | 填什么 | 缺了会怎样 |
|---|---|---|
| `region` | 参保地（**不是户籍地**） | 属地未采集 → 全部标〔待补〕 |
| `identity` | 在职职工 / 灵活就业 / 失业人员 / 男职工配偶 | 影响比例档位与基数口径 |
| `scenario` | 顺产 / 难产顺产 / 多胞胎双胞胎 / 多胞胎三胞胎 / 终止妊娠 / 计划生育手术 | 决定天数 |
| `base_wage` | **单位上年度职工月平均工资**（灵活就业填最低工资标准） | 算不出金额 |
| `own_wage` | 本人产假期间的月工资标准 | 算不出单位补足差额 |
| `contribution_months` | 生育前连续/累计缴费月数 | 判不了缴费是否达标 |
| `social_avg_monthly_wage` | 当地上年度全口径城镇单位就业人员月平均工资 | 算不了托底/封顶 |
| `received_allowance` | 已实际收到的津贴金额 | 算不出实收差额 |

### 动作二：跑测算

```bash
python scripts/maternity_benefit.py --input case.json
python scripts/maternity_benefit.py --input case.json --json     # 机器可读
python scripts/maternity_benefit.py --list-regions                # 看已采集属地
python scripts/maternity_benefit.py --selfcheck                   # 跑自检（13 项）
```

脚本**纯 Python 标准库、零 pip 依赖、不联网、不读环境变量、不写文件**（除读取你指定的输入 JSON 与同目录的 `regions.json`）。

### 动作三：拿核对单去对账

脚本输出四段：**应享受天数 / 计算基数 / 缴费连续性 / 应发金额**，每段都带依据。跟着三件事做：

1. **跟单位对基数** —— 拿你算出的"计算基数"问单位：上年度全部参保职工的月平均缴费工资是多少？如果单位报的数字明显低于实际，按《社会保险法》第八十六条，社保经办机构有权稽核。
2. **跟经办机构对天数** —— 把属地的天数构成和你的实际情况列出来问。特别注意**地方奖励假的那一格是单位发工资，不是津贴**——这一格常被单位整体按"98 天"算，等于把奖励假那部分工资也吞了。
3. **对差额** —— 脚本算出的"单位应补足差额"就是你要向单位主张的金额。证据是**工资流水 + 津贴到账记录**（证明实发低于应发），主张方式是**书面**（留痕，口头说过不算数）。

## 四、口径的三段结构（这是理解全部属地差异的钥匙）

不管哪个属地，生育津贴都拆成这三段：

```
应发金额 = 日计发标准 × 应享受天数 × 缴费比例（部分属地）
日计发标准 = 计算基数 ÷ 30
```

| 段 | 变的是什么 | 常见取值 |
|---|---|---|
| **天数** | 国家基础 98 天 + 地方奖励假 + 难产 +15 + 多胞胎每多一个 +15 | 北京 128 / 宁德 128 / 佛山 128 / 防城港 128（一孩二孩）·158（三孩） |
| **基数** | 用谁的平均工资 | 绝大多数属地：**单位上年度职工月平均工资**；宁夏灵活就业：一类地区月最低工资标准；失业人员：当地社平工资 |
| **缴费连续性** | 满几个月才由基金付 | 北京 9 个月 / 上海 12 个月（或连续 9 个月）/ 宁德 6 个月起分档 |

**第四段最容易被漏：单位补足差额。** 北京、上海、佛山都明文"津贴低于本人产假工资标准的，差额由用人单位补足"。这一段不是政策给的，是要自己去主张的。

**第五段属地特有：托底与封顶。** 北京、上海都规定：计算基数低于上年度本市职工月平均工资 **60%** 的按 60% 计，高于 **3 倍**的按 3 倍计。这条保护的是参保人，但只在**基数被如实申报**时才有效。

## 五、"少拿了钱"的六种典型情形

这是本技能最想让你记住的部分——**六种情形里，只有一种是"自己没算错"，其余五种都是可以主张的**。

| # | 情形 | 少拿多少 | 依据锚点 |
|---|---|---|---|
| 1 | 按本人工资而非单位平均工资算基数 | 差额 = （单位均值 − 本人工资）÷ 30 × 天数 | 防城港官方举例 |
| 2 | 单位整体压低缴费基数 | 同上，且影响全体女职工 | 北京/上海 60%-300% 托底封顶 |
| 3 | 地方奖励假被按"98 天"算 | 奖励假天数 × 日标准（**由单位发工资**） | 广东阳江明文"奖励假期间由用人单位发放工资" |
| 4 | 津贴低于本人产假工资，差额未补足 | 北京 12348 个例：应得 73733 / 实发 32000 / **差 41733** | 北京、佛山、上海明文 |
| 5 | 缴费连续性不足月数 | 津贴改由单位支付（单位不付=个人吃亏）；部分属地满一定月数后可由基金**补支** | 北京 9 个月 / 上海 12 个月 / 宁德 6 个月起 50%、满 12 个月 100% |
| 6 | 未参保/断保导致待遇中断 | 上海灵活就业：等待期内分娩，**2027-05-01 后不再享受津贴** | 上海 2026-10 通知 |

## 六、全国统一的那几笔（属地口径之外，不能漏）

这些与属地津贴**并行**，不是替代关系，算完属地津贴后单独核对：

| 项 | 标准 | 规模/进度 | 怎么领 |
|---|---|---|---|
| **育儿补贴** | 每孩每年 **3600 元**（每月 300 元）至满 3 周岁 | 2026 年中央财政下达 **999 亿元**（较上年 **+10.6%**），全年各级约 1100 亿元；截至 2026-07-21 已提交申请 **2751 万条**、已发放 **2516 万人** | 支付宝/微信/省级政务服务平台登录"育儿补贴信息管理系统"；2026 年新增**一键续领**；2022-2024 年出生的首次申请截止日**已延长至 2026-12-31** |
| **婴幼儿个税专项附加扣除** | 每孩每月抵扣 **2000 元** | — | 个税汇算期间在个税 APP 一键申报 |
| **生育医疗费用待遇** | 与津贴**并列**，不是二选一 | — | 分娩后核对是否已联网结算；未结算的按属地时限申请零星报销（例：广东阳江为**次日起 3 年内**） |
| **津贴直发个人** | 2025-12 起多数统筹区已直发个人账户 | — | 确认本属地是否已直发；未直发的向单位索取垫付凭证 |

**范围**：育儿补贴不分城乡、民族、区域，不分一孩二孩三孩，多孩可叠加，**免征个税、不计入低保家庭收入**。

## 七、属地覆盖与〔待补〕原则

已采集 7 个属地（见 `references/region-maternity-rules.md`，每条带官方原文 URL 与核验日期）：

| 属地 | 天数表 | 基数口径 | 缴费要求 | 特殊规则 |
|---|---|---|---|---|
| 北京市 | 98+30=128 | 单位上年度职工月平均工资 | 满 9 个月 | 不足 9 个月由单位支付，满 12 个月可补支；托底 60% / 封顶 300% |
| 上海市 | 待按上海条例核对 | 单位上年度职工月平均工资 | 满 12 个月或连续 9 个月 | 灵活就业 2025 起纳入，生育保险按 1% 缴费、津贴按社平 60%；过渡期至 2027-04-30 |
| 佛山市 | 顺产 128 | 单位上年度参保人员月平均工资 | 待补 | 失业人员按上上年度全口径社平；津贴免个税 |
| 阳江市 | 顺产 128 | 单位上年度所有职工月平均工资 | 待补 | 2025-12-01 前分娩由单位垫付；零星报销 3 年内 |
| 宁德市 | 顺产 128 | 单位上年度月平均工资 | 满 6 个月 | 6-11 个月按 50%，满 12 个月 100%；事业单位按原渠道领工资不享津贴 |
| 宁夏自治区 | 待补 | 在职：单位均值 / 灵活：一类地区最低工资 | 满 12 个月 | 2026-01-01 起灵活就业全面纳入；男职工两项补助金 |
| 防城港市 | 一孩二孩 128 / 三孩 158 | 单位上年度全体职工月平均缴费工资 | 待补 | 官方原例：按单位均值不按本人工资 |

**属地未采集时怎么办**：脚本输出〔待补〕，并给出**三个必须问经办机构的问题**：
1. 本人生育/流产时所在用人单位上年度职工月平均工资是多少（计算基数）
2. 本次应享受的生育津贴天数是多少天（国家基础 + 地方奖励假 + 难产 + 多胞胎）
3. 生育前连续缴费需满几个月才由基金支付；不满时津贴由谁出

**只要属地没采集，脚本不给数字。** 这是硬规则——宁可让用户去问，也不要给一个错的数。

## 八、法律与合规边界

- **只做算术与规则比对**，不做资格认定、不做金额承诺
- 每条结论都标依据属地与规则名，用户可回官方原文核对
- **属地口径有时效**：本包口径核验于 2026-11-02，生育支持政策 2025-2026 年密集修订，使用前须核对参保地当期文件
- 涉及与单位主张差额时，本技能只给**算式与证据清单**，不给话术、不代理谈判
- 标注〔待补〕的项**不得当作结论使用**
- 涉生育信息属个人敏感信息，脚本不联网、不落盘、不读环境变量

## 十、常见追问的答法

- **"生育津贴和产假工资能同时领吗？"** —— 不能重复领，按"就高不就低"：津贴高于产假工资的，只发津贴；**津贴低于产假工资的，单位要补足差额**。
- **"单位说没有生育津贴这回事"** —— 生育津贴是生育保险基金支付的，单位只是代申报和（或）垫付。单位不垫付且不申领，损失落在职工身上。
- **"我在上海灵活就业参保，能领吗？"** —— 2025-01-01 起已纳入生育保险，生育保险按 1% 缴费；津贴按本市上年度全口径社平工资的 **60%** 计发，需生育前累计缴费满 12 个月。**2027-05-01 起**还须在生育时正常享受职工医保待遇。
- **"产假一共多少天？"** —— 国家基础 98 天是底线，各地在 128 天（多数）、143 天（难产）、158 天（三孩/部分地区）之间。**精确数字按参保地。**
- **"为什么算出来和单位给的不一样？"** —— 三个可能：单位用了"奖励假也发津贴"的错误天数口径；单位用了自己的缴费基数而非上年度全员平均；或者单位按"累计"而非"连续"算了缴费月数。拿着脚本输出的三段口径逐段对。
