# 个人与小微企业退出案例集（六个典型场景）

> 说明：以下是典型的处置路径与踩坑点归纳，用于帮助用户快速定位自己属于哪一类、该先做什么。
> **金额、时限、比例均为量级示意，具体以当地机关与税务机关口径为准。**
> 案例已做匿名化与情境重构，不指向任何具体当事人。

---

## 场景一 · 电商个体户，经营两年后不做了，账上有 8 万未提

**老板的原话**："不做了，反正也没开多少票，扔掉算了。"

### 真实情况
- 两年共开票约 30 多万（含税），成本进项约 22 万
- 账上 8 万是**货款沉淀**（还没提现到银行卡）
- 从未做过零申报，有两个季度没申报

### 踩坑点
老板以为"没开多少票"= "不用管税"。实际上：
1. **有流水就必须申报**，两个季度未申报 → 税务会标记异常，注销时必须先补
2. 补申报时按什么口径申报，取决于实际经营情况，**这需要和主管税务机关确认**
3. 账上的 8 万是**清算所得**，分配给经营者时同样有个人所得税问题

### 正确处置顺序
```
① 先做"税务健康检查"（八项全过一遍）
② 补申报 + 处理异常状态
③ 算清楚 8 万的性质与税务处理方式 ← 这一步最容易出错
④ 决定是否走简易注销（大概率要走一般注销，因为有流水）
⑤ 清算组备案 → 税务注销 → 公告 → 工商 → 银行
```

### 给老板的关键提醒
**"不做了"不等于"不用申报了"**。不申报省下的是几百块，逾期申报带来的是滞纳金 + 异常状态 + 注销卡壳。

## 场景二 · 科技公司股东借款 30 万，运营两年半停止，股东想注销

**老板的原话**："公司是我自己的，钱我随时能拿回来，直接注销就行。"

### 真实情况
- 注册资本 100 万，股东借款 30 万（记在"其他应付款"）
- 银行流水显示近一年有 3 笔公司转给股东个人的款项，被标注为"备用金"
- 公司有 2 个社保在缴，员工已口头离职但未办停缴

### 踩坑点（这是最典型的雷）
1. **股东借款 30 万未还** → 注销清算时视同分红 → **个人所得约 6 万**
2. **个人从公司拿的"备用金"** → 同样可能被认定为个人所得
3. **2 个社保未停缴** → 简易注销的"债权债务已清"承诺**不实**

### 正确处置顺序
```
① 停止"备用金"做法（这是最需要立刻纠正的）
② 社保全部停缴并确认
③ 股东借款专项测算：
   - 方式 A：股东用个人资金归还 30 万到公司账户 → 往来冲平
   - 方式 B：依法按分红/减资处理 → 涉及个人所得税
   - 两种都摆给老板选
④ 税务健康检查八项全过
⑤ 因有经营流水 → 一般注销
⑥ 正常九步流程
```

### 给老板的关键提醒
**"钱是我的"在税务上是两回事**。公司账上的钱是公司的，股东拿走要按规则走。这一步如果现在不处理，注销时会集中爆发。

## 场景三 · 小规模纳税人，公司没业务但"每年零申报"，想注销省事

**老板的原话**："我一年报一次零申报，从来没出过问题，注销肯定也简单。"

### 真实情况
- 成立 4 年，每年只做过一次零申报，12 月
- 无开票、无欠税、股东无往来
- 但 **2025 年全年未申报**（今年忘了）

### 踩坑点
1. **只有零申报 = 大概率符合简易注销条件**，这是好消息
2. 但 2025 年未申报 → 状态异常 → **简易注销通道可能走不了**，要先恢复正常状态
3. 员工零申报但有开过发票的月份，要确认发票是否都已认证

### 正确处置顺序
```
① 先补 2025 年零申报（恢复状态）
② 核对发票存量（有没有开过票没认证）
③ 社保、公积金确认无在册人员
④ 健康检查通过后 → 尝试简易注销
⑤ 简易注销被拒 → 转一般注销
```

### 给老板的关键提醒
**零申报的连续性断了，就不再是"零申报企业"**。一年一次申报是很多人忽略的节点，注销前一定要把漏的补上。

## 场景四 · 餐饮店个体户，门店转让了半年，想注销

**老板的原话**："店转出去了，营业执照留着也没用，注销掉。"

### 真实情况
- 门店 8 个月前转让，转让费 20 万（老板个人收的）
- 餐饮经营期间有食品经营许可、员工、社保
- 转让后未做任何申报

### 踩坑点
1. **转让后必须做变更或停业报告**（按当地规定），不能"不管"
2. **转让费归个人还是公司** → 涉及是否需要纳入申报
3. 食品经营许可可能还有效，需一并处理
4. 员工有的还在原单位社保名单上（可能转租给了下家）

### 正确处置顺序
```
① 先确认门店转让后是否已做变更/停业报告
② 食品经营许可的处理（注销或变更）
③ 转让费归属的税务口径 ← 需向主管税务机关确认
④ 员工社保清理（含是否已转到下家）
⑤ 健康检查八项
⑥ 注销路径判断（有经营流水 → 一般注销）
```

### 给老板的关键提醒
**转让和注销是两件事**。转让后如果放任不管，等于"有经营行为却没申报"，这是最容易被认定为"非正常户"的状态。

## 场景五 · 公司被吊销（非正常户），老板想"重新注册一个"

**老板的原话**："反正注销也麻烦，我直接再开一家。"

### 真实情况
- 公司因未申报被吊销，已进入非正常户
- 名下有 2 家公司，其中一家异常
- 想注销这家、开一家新的

### 踩坑点
1. **非正常户状态下，简易注销通道基本走不通**，只能走一般注销（先恢复正常状态）
2. **异常户会影响法人**：影响银行开户、社保、后续注册
3. **原股东/法人的"开办登记"会留下记录**（"Dummy"公司、"光杆"公司会影响后续注册数量）
4. 有异常户时，税务会核查历史申报，可能追溯

### 正确处置顺序
```
① 先把异常状态处理掉（补申报、罚款处理、移出异常名录）
② 确认是否涉及欠税
③ 正常注销流程
④ 注意：原主体注销后，再注册新主体时，
   法人/股东会带上"曾任"记录，属正常，但需提前知道
```

### 给老板的关键提醒
**"注销麻烦"和"留着更麻烦"要算总账**。异常户对法人个人的影响（银行、社保、征信）通常比走完注销流程更麻烦。

## 场景六 · 公司有诉讼未结，老板想先注销"保住"

**老板的原话**："我先把公司注销掉，债主就找不到了。"

### 真实情况
- 公司作为被告，标的 50 万，案件在审理中
- 老板个人为公司做了担保

### 踩坑点（这是**最危险**的场景）
1. **诉讼未结的公司不能走简易注销**
2. **个人担保不因公司注销而免除** —— 债权人是可以对担保人主张的
3. **股东出资义务**：如果注册资本未实缴或未缴足，股东可能仍需承担出资责任
4. **试图"注销逃债"在法律上不成立**，且可能构成恶意逃债
5. 简易注销的承诺书虚假 → **注销可被撤销**，企业恢复原状

### 正确处置（这个场景必须建议咨询律师）
```
① 立即咨询执业律师了解案件与担保责任
② 不要提交任何注销承诺
③ 根据律师意见选择：应诉 / 调解 / 债务重组 / 依法清算
④ 注销必须等诉讼了结后按正常流程走
```

### 给老板的关键提醒
**注销不消灭债务，人格混同下股东本来就可能要承担**。真正要解决的是"债务怎么办"，不是"主体怎么消失"。这个问题请找律师，不要自己想办法。

## 通用处置框架（六个场景的共性）

```
┌────────────────────────────────────────────────────┐
│ 第一步：判断"是不是真的该注销"                        │
│   · 只是暂时不想做 → 停业/歇业可能更划算               │
│   · 转型但想保留主体 → 变更经营范围/股东               │
│   · 确实不做了 → 进入第二步                          │
├────────────────────────────────────────────────────┤
│ 第二步：判断"路径"                                    │
│   · 无经营行为 + 无债权债务 → 简易注销                 │
│   · 有流水/有债务/有诉讼 → 一般注销                    │
│   · 异常户/欠税 → 先恢复正常状态                       │
├────────────────────────────────────────────────────┤
│ 第三步：注销前八项健康检查（尤其是股东借款与担保）       │
├────────────────────────────────────────────────────┤
│ 第四步：按九步顺序办理（税务在前、银行在后）             │
├────────────────────────────────────────────────────┤
│ 第五步：留存全套凭证（清算报告、承诺、完税证明等）       │
└────────────────────────────────────────────────────┘
```

## 一句话总结六个场景的共同教训

> **六个场景里，五个的根因都是同一个：老板以为"注销 = 走个流程"，实际上"注销 = 一次财务清算"。**
> 而 67% 的申请被驳回或反复补正，恰恰是因为那些"没人提醒你的决定"被跳过了。

**本专家的价值就是：让老板在按下提交之前，把这些决定做完。**
