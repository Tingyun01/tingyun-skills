# 变更签证流程 · 验收留痕 · 结算对账

> 用于合同履行过程中的变更管理、交付验收与结算核对。本文是流程与材料准备辅助，不构成法律专业意见，需人工复核。

## 一、变更为什么要书面化（判断逻辑）

变更的本质是**合同内容发生了改变**。判断是否需要走正式变更单，只问三个问题：

1. 做什么变了吗？（范围/交付物）
2. 做多少变了吗？（数量/工作量）
3. 多少钱、什么时候变了吗？（价款/工期）

三个问题里只要有一个答案是"是"，就是变更，必须书面。**只影响沟通方式的（澄清、催办、确认收到）不是变更**，书面回复留痕即可。

| 形态 | 典型场景 | 处理方式 | 留痕物 |
|---|---|---|---|
| 实质变更 | 加需求、改规格、改工期、改价格 | 变更单/补充协议，双签 | 变更单原件 + 附件 |
| 执行细化 | 澄清技术参数、确认清单、补发附件 | 书面回复确认 | 邮件/签收单/回复函 |
| 口头误解 | 双方对同一句话理解不同 | 先书面复述理解一致 | 澄清函，双方确认 |
| 对方单方要求 | 甲方口头追加、即时通讯上说"再加个功能" | 回函确认收到 + 判断是否构成变更 | 回函 + 后续变更单 |

## 二、变更处理六步（可直接做成流程）

```
第 1 步 登记：收到任何变更信息，24 小时内在台账登记"变更待判定"
第 2 步 判定：按上一节三问判定属于哪种形态
第 3 步 评估：影响四栏——范围、工期、价款、其他（付款节点/验收标准是否连带变动）
第 4 步 决策：内部审批（谁批、预算从哪来、要不要调整整体计划）
第 5 步 书面：出变更单或补充协议，双方签署（用印/签章要求与主合同一致）
第 6 步 回写：变更单编号入台账，联动更新金额、工期、节点日期、验收标准
```

### 变更单必备要素（8 项）
1. 关联合同编号 + 变更单编号；
2. 变更事由与背景；
3. 变更内容（做什么：具体到条目/清单，不写"优化一下"）；
4. 对工期的影响（顺延多少天，或不涉及）；
5. 对价款的影响（增减金额 + 币种 + 合计 + 含税口径）；
6. 对其他条款的影响（是否改变验收标准、付款节点、质保责任）；
7. 生效条件与生效日期；
8. 双方签署栏（主体名称、盖章、日期、联系人）。

### 三条常见的坑
- **只写增加不写替代**：变更后原第 X 条是否仍然有效要写明，否则将来出现"到底按新的还是按旧的"。
- **只改价不联动付款节点**：金额变了，但结算节点还是按原金额比例走，必然对不上账。
- **变更单与主合同冲突时不知以谁为准**：变更单里加一句"本变更单生效后，与主合同不一致的，以本变更单为准"，这是常见做法，具体写法请交由专业人士审阅。

## 三、交付与验收证据留存清单

### 核心原则
争议发生后，能证明的不是"我做了"，而是"**对方知道并且接受了**"。所以证据要覆盖三段：**我方做了 → 对方收到 → 对方认可**。

### 清单（按四类归档）

**A. 交付物本身**
- 交付物清单（逐项列明名称、版本/数量、介质）；
- 交付记录（发出方式、发出时间、接收人、签收人）；
- 对方签收单 / 收件回执 / 系统下载记录。

**B. 验收过程**
- 验收申请（我方发起的时间与方式，证明不是被动等待）；
- 验收标准依据（合同条款、附件标准、图纸、变更单编号）；
- 验收单 / 确认单（双方签署，日期齐全）；
- 验收意见与遗留问题清单（含整改期限、责任人）；
- 复验记录与闭环证明。

**C. 过程留痕（防"我做过但拿不出证据"）**
- 往来函件与会议纪要（按时间排序，含参会人）；
- 关键节点截图/照片（带时间信息）；
- 变更沟通记录（邮件、函件、审批单）；
- 我方交付前自检/测试记录。

**D. 结算与付款**
- 开票申请与发票存根（票号、金额、日期、税额口径）；
- 付款申请与银行回单/到账凭证；
- 对账确认函或双方确认的对账记录。

### 验收单缺失时的补救顺序（不要跳步）
1. 先自查：我方是否发过书面验收申请（有申请记录 → 责任在对方等待；无申请记录 → 我方流程有缺口）；
2. 有申请记录：发书面确认函（附交付物清单与签收证据），请对方在指定期限内确认，逾期未回复的说明写进函里；
3. 无申请记录：补做一次完整的验收申请流程（同时说明交付时间），把流程补齐再推进；
4. 对方明确拒绝验收或拒签：记录拒签事实与理由，升级并建议咨询专业人士，不要自行代签或伪造签认。

> 明确禁止：代签验收单、补签日期倒填、伪造签收记录。这类做法在争议中通常不被采信，还可能引出更严重的责任。

## 四、结算与开票节点的对账方法

### 对账四栏法
把每一笔应收拆成四栏，逐笔核对：

| 栏位 | 含义 | 取数来源 |
|---|---|---|
| A 应做 | 合同约定该做多少 | 合同 + 已签变更单 |
| B 已做 | 实际完成多少 | 交付记录 + 验收单 |
| C 已开票 | 已向对方开多少 | 发票存根 |
| D 已收 | 实际收到多少 | 银行流水 |

### 差额定位（按 A→B→C→D 顺序查，不要跳）
- **A≠B**：工作量/范围口径不同 → 查是否有未签变更、是否有未验收部分、含税口径是否一致；
- **B≠C**：做完了没开票 → 查开票前置条件（是否需对方确认/发票信息/内部审批）；
- **C≠D**：开票了没到账 → 查是否被退票、对方是否声称未收到、是否付到第三方账户；
- **D < B（且已确认）**：对方欠款 → 转入催收动作清单（措辞见下）。

### 对账确认的落地形式
1. 发**对账单**（列 A/B/C/D 四栏 + 差异说明），请对方书面确认或提出异议；
2. 对方有异议 → 逐笔标注争议项与不争议项，只追争议项，不争议项先按已确认推进；
3. 双方书面确认的对账单，本身就是后续主张的重要材料（证明双方对账口径达成一致）。

### 催款措辞的安全边界
**可以写**：
- 事实陈述 + 合同条款引用 + 已完成事项 + 明确回复期限；
- "按合同第 __ 条，我方已于 __ 日完成 ___，贵方应于 __ 日前支付 __ 元，请于 __ 日前书面确认付款安排"；
- "若对金额有异议，请于 __ 日前提出具体异议项，以便逐项核对"。

**不要写**：
- 威胁性、施压性表述（曝光、投诉、上网、发黑材料等暗示）；
- 断言式、夸大式措辞（"必然""一定""必定"）；
- 结论性法律判断（"贵方已构成违约，须赔偿 __ 元"这类定性交给专业人士）；
- 未经核实的因果归因。

> 欠款催收的具体话术与法律手段选择（函件、支付令、诉讼等）涉及法律判断，请交由持证法律专业人士决定。

## 五、结算阶段的常见断点对照表

| 症状 | 多半卡在哪 | 优先动作 |
|---|---|---|
| 活干完了，对方不回应 | 验收申请没发或发了没留痕 | 补书面验收申请 + 函件 |
| 对方说"做的不符合要求" | 验收标准没提前明确 | 找合同/附件标准条款，逐条比对，出差异说明 |
| 双方金额算得不一样 | 变更未签、口径不一致 | 先统一口径（是否含税、是否含变更、是否扣款） |
| 发票开了对方不认 | 交付证据链缺一环 | 补签收/验收证据链 |
| 钱到了但台账没销 | 财务未核销 | 财务核对流水并回写台账 |
