# 跨境传输前自检清单与事件处置顺序

> 用途：给工程师一张每次传输前能勾的表；给管理层一条出事时能照着走的处置顺序。
> 内容为清单与流程梳理，不构成法律专业意见，需人工复核。

## 一、跨境传输前自检清单

用法：每次新增或变更出境链路时跑一遍；跑完后把结论写进台账。**建议在流水线里加一道人工确认卡**，勾选表作为卡的附件。

### A. 链路识别

| 编号 | 检查项 | 勾选标准 | 不通过怎么办 |
|---|---|---|---|
| A1 | 本次变更是否新增或改变了出境链路 | 能明确说出链路编号、涉及系统、数据集 | 不明确就停下，先画数据流图 |
| A2 | 境外接收方是谁、在哪个法域、什么角色 | 名称、法域、角色（受托/共同/独立）三项齐全 | 补齐再往下走 |
| A3 | 传输形态是什么 | 实时同步 / 批量导出 / 接口调用 / 远程登录 / 备份同步，明确其一或多项 | 形态不清视为高风险，按形态分别检查 A4~A6 |
| A4 | 是否存在"境外可查询、调取、下载、导出"的通道 | 已排查全部后台、运维通道、工单系统 | 存在即落入出境场景 |
| A5 | 是否存在间接出境路径（备份、灾备、遥测日志、工单、开发测试环境、境外运维登录） | 六项逐项排查并记录结论 | 任一项命中即纳入本次出境范围 |
| A6 | 是否使用境外人工智能或分析类第三方服务，传入内容含个人信息 | 已确认传入字段清单 | 含个人信息即按出境处理并补路径 |

### B. 数据定性

| 编号 | 检查项 | 勾选标准 | 不通过怎么办 |
|---|---|---|---|
| B1 | 本次出境的数据类别 | 逐个数据集标注：个人信息 / 敏感个人信息 / 重要数据 / 一般数据 | 回到字段级分类，不能在数据集层拍脑袋 |
| B2 | 是否含重要数据 | 已查本行业重要数据识别指南是否覆盖；已记录识别与申报状态；已确认是否被告知或公开发布 | 未覆盖且未被告知的，按令第16号第二条处理但要留痕；被告知的必须走安全评估 |
| B3 | 是否含敏感个人信息，具体哪些类别 | 类别写明 | 未识别则补识别 |
| B4 | 是否已公开 | 明确已公开或未公开 | 状态不明按未公开从严处理 |
| B5 | 是否已做匿名化且不可复原 | 有去标识化方法说明 + 技术不可重识别验证 + 精度与样本量控制记录 | 仅脱敏、可复原、可通过外部数据关联的，不算匿名化 |

### C. 数量与档位

| 编号 | 检查项 | 勾选标准 | 不通过怎么办 |
|---|---|---|---|
| C1 | 本次出境涉及的自然人数、敏感个人信息人数分别是多少 | 有数字，不是"不多" | 出统计表 |
| C2 | 统计口径是否自当年1月1日起累计 | 口径、起始日均写明 | 重算 |
| C3 | 是否跨链路、跨系统合并统计 | 已与累计人数统计表核对 | 合并后重判档位 |
| C4 | 是否存在为规避门槛而拆分的情形 | 无拆分 | 有拆分立即停止并重判路径 |
| C5 | 落在哪一档 | 给出档位与依据条款 | 查分档表 |
| C6 | 是否命中豁免闸门 | 命中则写明条款与需留存的证据 | 未命中按正常路径走 |
| C7 | 是否为关基运营者身份 | 明确是或否 | 影响整条判断链 |

### D. 路径动作

| 编号 | 检查项 | 勾选标准 | 不通过怎么办 |
|---|---|---|---|
| D1 | 该档要求的动作是否已完成 | 逐项有完成日期与材料位置 | 未完成不得上线该链路 |
| D2 | 告知内容是否完整 | 含境外接收方名称、联系方式、处理目的、方式、种类、保存期限、权利行使方式与程序 | 补告知 |
| D3 | 单独同意是否已取得且对应本场景 | 同意记录可追溯到本次出境场景与字段 | 补取得；不能补则不上线 |
| D4 | 个人信息保护影响评估是否已做并覆盖本次变更 | 报告版本、日期、六项评估要点全覆盖；涉及变更的已出修订版 | 补评估 |
| D5 | 敏感个人信息的必要性说明与单独同意是否到位 | 两项均有 | 补 |
| D6 | 与境外接收方的法律文件是否按要求订立 | 标准合同路径用网信部门发布的范本文本且未改核心条款；约定处理目的方式范围与安全义务 | 改签或重签 |
| D7 | 境外接收方履约能力材料是否齐备 | 资质、安全认证、审计报告、子处理者清单 | 补齐 |
| D8 | 评估结果 / 标准合同 / 认证是否在有效期内 | 有效期未过 | 过期则重新判断路径 |
| D9 | 拟出境范围是否超出已通过评估或备案的范围 | 不超出目的、方式、范围、种类、规模 | 超出则重新申报或调整场景 |
| D10 | 记录留存要求 | 提供与委托处理记录已保存，保存期不少于3年 | 建档 |

### E. 合同与供应商

| 编号 | 检查项 | 勾选标准 | 不通过怎么办 |
|---|---|---|---|
| E1 | 合同是否约定处理目的、方式、范围与安全义务 | 逐项列举 | 补条款 |
| E2 | 是否约定再委托与共同处理规则、变更通知提前期 | 有 | 补 |
| E3 | 是否约定个人权利请求响应流程与时限 | 有 | 补 |
| E4 | 是否约定审计与检查权 | 有 | 补 |
| E5 | 是否约定泄露通知时限与配合义务 | 有 | 补 |
| E6 | 境外子处理者是否已全部披露 | 清单齐全 | 补披露 |
| E7 | 收款主体、签约主体与实际提供服务方是否一致 | 一致 | 不一致须说明关系与责任承担 |

### F. 技术与留痕

| 编号 | 检查项 | 勾选标准 | 不通过怎么办 |
|---|---|---|---|
| F1 | 传输链路是否有访问控制与权限收敛设计 | 权限清单与角色对应 | 收敛权限 |
| F2 | 境外访问是否留日志，日志是否可导出用于举证 | 有日志且可导出 | 补日志能力 |
| F3 | 加密与脱敏措施是否与影响评估结论一致 | 一致 | 修正或改评估 |
| F4 | 台账记录是否已填写完整 | 两层台账字段齐全，可指向材料位置 | 补 |
| F5 | 有效期与复核台账是否已更新 | 到期日与责任人明确 | 补 |

### G. 上线后复查

| 频率 | 复查项 | 触发动作 |
|---|---|---|
| 每月 | 数量累计是否跨档 | 跨档则重新走 C、D 两段 |
| 每季度 | 有效期与复核台账 | 到期前启动延长或重办 |
| 每半年 | 间接出境路径（遥测、工单、开发环境）是否新增 | 新增则回到 A5 重新判断 |
| 每年 | 数据分类分级台账、重要数据识别与申报状态 | 更新识别申报留痕；涉重要数据的按要求报送年度风险评估报告 |

## 二、数据泄露事件的处置顺序

适用场景：境外接收方、云服务商、外包服务商告知发生数据安全事件，或自查发现数据已非预期流出。

**核心原则**：顺序不能跳，报告不等结论。

```
第 1 步 止损
  立即切断继续外流的通道：暂停同步任务、吊销令牌与账号、冻结导出接口、撤销临时授权
  不要先开会讨论责任，先关水
  同时保留操作记录，不要急着清理日志

第 2 步 定位范围
  确认四件事：哪些数据（字段与类别）、哪些自然人（人数与去重口径）、哪些时间段、经过哪条链路流出
  区分"已流出"与"可能被访问"，后者也要按已流出准备

第 3 步 报告
  依据：《网络数据安全管理条例》第十一条（发生数据安全事件应当立即启动预案、采取措施防止危害扩大、消除安全隐患，并按照规定向有关主管部门报告；
  对个人、组织合法权益造成危害的，应当及时告知安全事件和风险情况、危害后果、已经采取的补救措施；
  处置过程中发现涉嫌违法犯罪线索的，应当向公安机关、国家安全机关报案并配合侦查）
  依据：《促进和规范数据跨境流动规定》第十一条（发生或者可能发生数据安全事件的，应当采取补救措施，及时向省级以上网信部门和其他有关主管部门报告）
  要点：报告义务在"发生或者可能发生"时即触发，不要求先查清全部事实；定性结论由主管部门作出

第 4 步 告知个人与利害关系人
  内容：安全事件与风险情况、危害后果、已采取的补救措施
  方式：依规定可用电话、短信、即时通信工具、电子邮件或公告等方式；法律、行政法规规定可以不通知的依其规定
  要点：告知内容要具体，"我们发生了泄露"不构成有效告知

第 5 步 追溯与留证
  固化：访问日志、链路记录、告警记录、与境外接收方的往来记录、排查过程记录
  形成时间线：何时发现、何时止损、何时报告、何时告知、每次动作的操作人
  目的：为后续核查、追责与整改提供完整证据链

第 6 步 复盘与整改
  修订：自检清单、合同条款、权限设置、告警规则
  重判路径：若泄露范围超出原申报或备案的范围，重新判断路径
  台账更新：记录事件、处理过程、整改结果
```

**常见处置失误**：

| 失误 | 后果 |
|---|---|
| 先花两周查清全部事实再报告 | 报告义务已触发，迟报本身构成问题 |
| 只通知境外接收方，不报监管 | 报告义务在境内主体，不在境外方 |
| 清理日志与服务器镜像 | 证据灭失，后续核查与追责无据 |
| 口径未定就对外发布说明 | 与监管认定、个人告知口径不一致，纠正成本更高 |
| 只处理技术侧，不通知法务与业务 | 合同责任、个人权利响应、外部披露环节全部漏掉 |

## 三、必须委托专业机构或咨询主管部门的情形

出现下列任一情形，不要自行继续处理，直接对接专业机构或主管部门。

### 3.1 应委托专业服务机构

| 情形 | 建议对接的方向 |
|---|---|
| 涉及重要数据出境 | 数据合规服务机构 + 行业主管部门沟通渠道 |
| 属于关键信息基础设施运营者 | 需要具备关基资质经验的服务机构同步推进内部流程与主管部门沟通 |
| 敏感个人信息规模达到万人量级 | 需评估路径与告知同意方案的合规稳健性 |
| 已发生或疑似发生安全事件，需要跨法域取证 | 具备跨境取证与安全事件响应能力的服务机构 |
| 需要就具体法域的监管口径出具意见 | 目标法域的本地法律服务机构 |
| 涉及跨境税务、数据交易、合同安排 | 财税与合同专业服务机构 |
| 重要数据识别与申报无行业指南可依 | 熟悉主管部门沟通机制的专业机构 |

### 3.2 应咨询主管部门

| 问题类型 | 咨询方式 |
|---|---|
| 本行业、本领域数据是否属于重要数据 | 行业主管部门 |
| 本链路应落在哪一档、是否命中豁免 | 所在地省级网信部门 |
| 自由贸易试验区负面清单是否覆盖本链路 | 自贸区管理机构与省级网信部门 |
| 数据出境安全评估申报材料与流程 | 所在地省级网信部门；线上可通过数据出境申报系统提交 |
| 标准合同备案的受理与材料要求 | 所在地省级网信部门 |
| 个人信息保护认证的认证机构与规则 | 网信部门与市场监管部门 |
| 数据安全事件报告的渠道与格式 | 所在地省级网信部门及其他有关主管部门 |

**咨询前先准备好**：链路图、字段清单与分类结论、数量累计统计与口径、数据类型判定依据、已完成的义务清单、想问的具体问题（一次问清，不要零散问）。主管部门答复的书面记录要归档进台账。

### 3.3 应向公安机关或国家安全机关报案的情形

处置数据安全事件过程中发现涉嫌违法犯罪线索的，按《网络数据安全管理条例》第十一条向公安机关、国家安全机关报案，并配合开展侦查、调查和处置工作。线索判断不要自己下结论，交给办案机关，但线索要报。

### 3.4 需要外部专业力量才能推进的自查

| 场景 | 缺口 |
|---|---|
| 无法判定境外接收方所在法域对标准合同履约的影响 | 缺目标法域专业判断 |
| 拿不到境外接收方的实际安全措施与审计报告 | 缺境外尽调渠道 |
| 历史链路规模不明、累计人数无法还原 | 缺历史数据与还原方法 |
| 存在境外分支的集团内数据调用 | 缺集团层面数据流全景 |
| 曾以"量小"为由未做路径判断的历史链路 | 缺历史链路的重新分档能力 |
