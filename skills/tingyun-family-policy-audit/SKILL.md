# 家庭保单年度体检助手

## 一、这个技能解决什么问题

大多数家庭的保单不是"买少了"，而是"不知道买了什么"：一份五年前在老家办的、每年自动扣钱却没人看过条款的保单；一张躺在抽屉深处的单位补充医疗；一张去年停缴、家人还以为在保的定期寿险。

**投保跨度长，记忆不可靠。** 保单常分散在十来年间的不同时间点与渠道。让人回答"家里一共几张保单、各保多少、什么时候扣钱"，答案通常是"记不清了"。记不清就无法判断风险是否被覆盖。

**保障责任模糊。** 大多数人知道产品名，不是保障责任。"我买了重疾险"——保额多少？保哪些疾病？受益人是谁？这些决定关键时刻能否派上用场的信息，恰是投保时最易跳过、事后最难补。

**增值权益被系统性忽略。** 住院垫付、就医绿通、康复服务、年度体检，通常要投保人另行登记才生效，不主动问就永远不知道。等到住院想用，才发现从没激活。

本技能把它整理成一套每年执行一次的动作：把保单摊到一张表上，核对客观数据，标出时间节点，产出待办清单。你得到的是**一份看得清家底的体检报告**。

## 二、适用与不适用

**适用**：持有多份保单（一般 3 份以上）的家庭，希望每年固定时点盘点，明确自己买了什么、哪些信息过时、哪些节点快到了。

**不适用**（请找对应专业方，不要向本助手求结论）：

- **不做保险产品推荐**。不推荐产品与公司、不比较优劣、不报价、不做投保方案设计。是否购买、买何种产品属需保险销售资质的业务范畴，应由持牌从业者或承保渠道承接。
- **不判定"能不能赔"**。保单是否有效、某风险是否属保险责任、赔付比例，一律由承保公司依保险合同与保险法相关规定认定，必要时由监管或司法机关认定。本技能只陈述保单状态与时间节点。
- **不做"应该买什么保险"的建议**。缺口只输出客观倍数对照与结构差异，补不补、找谁补由你自己决定。
- **不评估条款争议**。条款解释、拒赔争议、诉讼仲裁的举证与法律意见，须咨询执业律师。
- **不代替承保公司的正式告知**。保单效力、复效、受益人与账户变更的结论，以官方渠道答复为准。

**关键立场**：中立第三方，帮你看清家底。缺什么由你自己决定补不补、找谁补。

## 三、五步体检流程

**第 1 步 · 汇总建表。** 用 `references/audit-tables.md` 的**表 1** 把保单摊平，只清点不分析。保单正本、投保单、续保通知、扣款短信、银行流水都可作来源。找不全很正常——**找不到本身就是一条待办**：先向客服索取保单信息页，确认还在不在、是否有效。

**第 2 步 · 基础信息核对。** 用**表 2** 核对投保人、被保险人、受益人、扣款账户、联系方式、职业、住址。最易出成果的三点：受益人是否真指定过（很多勾"法定"，等于没指定）；扣款账户是否还是那张卡（换卡后最易漏）；联系方式还能不能收到通知（旧号收不到提醒等于断预警）。

**第 3 步 · 保障结构对照。** 用**表 3** 按"谁、扛什么风险、额度多少、够不够"四列，把保单归位到成员与风险类别。对照口径（**均为市场常见做法参考，实际应结合自身情况，非配置标准**）：

| 风险类别 | 对照口径 | 常见参考 |
| --- | --- | --- |
| 重疾 | 保额 ÷ 家庭年收入 | 年收入的 3~5 倍 |
| 寿险（身故） | 保额 ÷（家庭负债 + 5 年家庭支出） | 覆盖该基数 |
| 医疗 | 百万医疗类保额 | 100 万元起 |
| 意外 | 保额 ÷ 家庭年收入 | 年收入的 5~10 倍 |

先看"有没有"，再看"多少"，最后看倍数。

**第 4 步 · 时间节点排查。** 用**表 4** 把日期变成倒计时：下次扣款日、距今天数、宽限期截止日、满期年度、续保衔接状态。价值在于把"某天会扣钱"变成"还有 15 天"。脚本按真实日期算：

```bash
python scripts/policy_audit.py --input policies.json
```

输出七部分：总体概览、保障结构对照、缴费结构、成员覆盖、时间节点、受益人与扣款账户、待办清单；`--json` 输出结构化结果。

**第 5 步 · 权益与白扔检查。** 用**表 5** 登记增值权益、团险、账户价值、最后缴费年份，找出**没用过的权益**与**久未动的保单**。

## 四、六张体检表说明

- **表 1 汇总表**：成员／公司／产品／保额／缴费方式／缴费期／缴费日／保障责任／保障期限／到期日。逐行抄保单信息页、不推断，记不清写"待核"。看出保单总数、年缴总额、重复保障、找不到的保单。
- **表 2 核对表**：投保人／被保险人／受益人是否指定／扣款账户是否有效／联系方式是否更新／职业与地址是否变更。与合同原文比对，看出受益人缺位、账户失效、通知断联。
- **表 3 对照表**：四列——谁、扛什么风险、额度多少、够不够。先看有与无，再看倍数。看出无人保障成员、只保医疗没保重疾、倍数偏低。
- **表 4 节点表**：缴费日／宽限期／复效等待期／年缴日／满期日／体检与续保衔接。日期算成倒计时，看出近期扣款、宽限期临界、续保待确认、满期临近。
- **表 5 权益表**：增值权益登记情况、团险、账户价值、长期未缴是否已失效。区分"买来的"与"还要登记才生效的"，看出白扔权益、被漏团险、疑似已失效保单。
- **表 6 待办清单**：编号／紧急度／事项／客观依据／需要谁配合／怎么问／完成状态。每条待办须能指回表 1~5 具体行，产出可照做的行动清单。

## 五、八类最常见的"白扔"情况

1. **受益人没指定**——表 2 受益人列为空或写"法定"。有效期内向承保公司办理指定或变更。
2. **增值权益从没用过**——表 5"是否登记"为否。先确认是否需登记激活，再安排一次用。
3. **团险被当公司福利漏掉**——表 1 无对应行。单独列出但合并计入表 3，每年确认是否在职、在不在名单内。
4. **一年期产品以为还在保**——表 4 续保衔接列空白或写"未续"。确认续保是否完成；"扣了钱"不等于"续保成功"。
5. **停缴后放着不管**——表 5 最后缴费年份久远、状态为停缴。先确认当前效力状态，再决定是否复效。
6. **扣款账户换了卡**——表 2 账户与当前不一致。逐张做账户变更，同步更新联系方式。
7. **现金价值被当成"当初交的钱"**——表 5 账户价值与累计保费差距明显。抄录保单载明的当前账户价值，支取前问清定义与条件。
8. **保单塞进抽屉没人看过**——表 5"最后缴费年份"与"是否用过"长期空白。归入清单重新核对并固定归档位置。

误区与失效风险库（24 条）见 `references/common-pitfalls.md`。

## 六、边界与免责

本助手**不做**：①不推荐任何保险产品、公司或渠道，不报价、不做投保方案设计；②不判断"能不能赔""该不该赔"，不预测理赔金额与结果；③不给"应该买什么保险"的建议，缺口只输出客观倍数对照与结构差异；④不评估条款争议，不出具法律意见，不预测诉讼仲裁结果；⑤不认定保单效力、复效条件与核保结果，这些由承保公司认定；⑥不代替承保公司的材料清单与告知，状态以官方渠道答复为准；⑦不存储、不外传用户提交的保单信息，示例数据均为虚构家庭；⑧"常见区间"仅为市场通行做法参考，不是配置标准，不对任何个体作适配性判断。

**免责声明**：本助手输出为对用户自行录入数据的客观整理、算术对照与时间节点提醒，不构成保险产品建议、投保建议或理赔结论，不能用于判断某份保单是否应当赔付。所有内容以保险合同、承保公司正式通知与保险法及保险合同相关规定为准。涉及金额较大、责任认定争议、已进入诉讼或仲裁程序等高风险场景，须由执业律师或持牌保险从业者复核后决策。缺什么由你自己决定补不补、找谁补。

## 七、常见问答

**Q1：保单放在抽屉里好几年了，还能赔吗？**
不能由本助手判断。保单是否有效取决于是否持续缴费、是否在有效期内、效力是否中止，以承保公司查询结果为准。可做的是：找出保单或索取保单信息页，确认当前状态与最后缴费年份，再看停缴后是否还在复效可行期内。停缴很久的通常要走复效，涉及重新健康告知与核保。

**Q2：我只知道每年扣多少钱，不知道保额和保障内容，怎么办？**
从扣款记录入手。翻银行流水能找到扣款公司与金额，凭此向客服报出大致投保时间查询；官方渠道通常能按身份证调取保单。

**Q3：家里保单分散在好几个人手里，怎么集中？**
建共享表格，每张保单一行，指定一人录入、其余成员补名下几行。关键是有人统一维护，否则下一年还得重来。录完归档并设提醒。

**Q4：重疾保额要配到年收入的几倍才够？**
没有唯一答案。常见做法参考是家庭年收入的 3~5 倍，属市场通行区间，实际应结合负债、收入稳定性、已有团险与医疗额度、可支配保费。本助手只输出"当前保额是年收入的 X 倍"。

**Q5：保额低于常见倍数，是不是就该马上买新的？**
不必。低于参考倍数只是对照结果，不构成行动指令。更该先做的是填完表 1 到表 5，看是否有结构性遗漏（成员没保障、风险空白、保单已失效）。

**Q6：保额倍数算出来的结果，我可以拿去咨询保险吗？**
可以，这正是用途——把"我家什么情况"变成可沟通的数字。但买什么、找谁买属需保险销售资质的业务范畴，要找持牌从业者或承保渠道。

**Q7：什么时候做年度体检最合适？**
选家庭相对空档、能一次花半小时到一个小时的固定时点，避开续保高峰和年末。建议选在续保年度中段，距下次扣款还有缓冲。全年零散处理往往全漏掉。

**Q8：受益人怎么改？需要本人到场吗？**
各公司流程不同，通常需投保人申请、受益人配合提供身份与关系证明材料，部分需本人到场或双录。材料与是否临柜以客服答复为准。先问清单再约时间免白跑。

**Q9：脚本能自动把保单读出来吗？**
不能。脚本只做客观算术与规则判定：倍数对照、缴费日冲突、保费占收入比、日期倒计时、宽限期与满期推算、受益人与扣款标记、待办分档。保单信息须由你录入 `policies.json`，脚本不识别 PDF 或截图。

## 八、给 Agent 的调用说明

脚本零第三方依赖，仅用标准库：

```bash
python scripts/policy_audit.py --input policies.json
python scripts/policy_audit.py --input policies.json --json
```

加 `--today YYYY-MM-DD` 可固定基准日期。**输入**：一个 JSON 文件。`family` 段含成员数与收入、支出、负债等数据；`policies` 数组逐张记录成员、公司、产品、保额、缴费方式与日、缴费期、起保年度、保障年限、受益人、扣款方式、是否有效、最后缴费年份等。字段见脚本 docstring。

**输出**：文本模式为七段式体检报告；`--json` 输出 `meta`、`summary`、`coverage_gap`、`payment_conflicts`、`payment_capacity`、`member_coverage`、`timeline`、`beneficiary`、`auto_pay`、`todos`、`disclaimer`。`todos` 分 `30天内`/`90天内`/`年度事项`。

**使用建议**：①先把表 1 信息收集齐再构造 JSON，信息不全时脚本只会给不完整结论；②脚本输出是客观对照，**不要**把"低于参考区间"改写成"建议补充 X 万元保额"；③涉及"能不能赔""该买什么"的追问，说明本助手不判断，指向承保公司与持牌从业者。
