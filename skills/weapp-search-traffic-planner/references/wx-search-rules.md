## 二、账号基本信息与命名（自检表依据 A 组）

来源：S1「微信小程序账号基本信息规范」

| 条款要点 | 自检表对应行 |
|---|---|
| 账号基本信息不得含政治敏感、色情、暴力血腥、恐怖内容及法律法规禁止内容 | 基础合规行 |
| 不得混有**商业化用语、热门公众号或小程序名称、热门应用名称、流行用语、"国家级""高级"等广告法禁用的用语、水印标识**等与功能或内容无关的内容 | 商业化用语行 + 极限词行 |
| 官方举例：名称为「免费自助餐」「女装巨便宜」「名牌包包清仓」，含"免费""巨便宜""清仓"，**建议删除商业化用语，修改为品牌与产品描述或功能描述的结合** | 商业化用语行（官方反例） |
| 未经授权不得使用第三方享有合法权益的**商标、品牌标识**或相似内容、特殊角标，侵犯他人知识产权；也不得侵犯肖像权、名誉权、隐私权、姓名权等 | 商标授权行 |
| 官方举例：未授权使用微信品牌，名称为「微信小助手」的小程序，属于侵权行为 | 商标授权行（官方反例） |
| 无正当理由，账号名称**不能与已有小程序或公众号、热门应用名称产生重复或混淆**；不能使用**广义归纳类、普遍且不具有识别性的词汇**来命名；**或在名称中包含热门搜索词及关键词堆砌，与搜索系统进行规则对抗** | 通用词行 + 堆砌行 + 混淆行 |
| 官方举例：名称为「短裤短裙」的小程序，**建议修改为品牌与产品描述或功能描述的结合** | 通用词行（官方反例） |
| 注册明星粉丝团、后援会等账号，须提供经纪公司（工作室）授权或认证，未经授权不能注册 | 特殊主体行（仅相关行业） |

### 混淆行为条款（S1「混淆行为」）

| 条款要点 | 自检表对应行 |
|---|---|
| **无正当理由，小程序名称、头像、简介等信息不得与已有小程序、公众号、热门应用或其他具有一定影响的商业标识相同或近似，使普通用户难以区分** | 混淆行 |
| **小程序名称不得仅由不具有识别性的通用词、品类词构成，不得在名称、简介中堆砌热门搜索词或与自身服务无关的关键词，以获取与其服务不匹配的搜索展示位置** | 通用词行 + 堆砌行（这条同时管搜索，**合规与搜索是同一组红线**） |
| 处理规则：一经发现将根据违规程度对该小程序采取**风险提醒、限制功能直至封号**处理 | 风险提示 |

> 🔴 **重要推论**：把关键词堆在名称里换搜索曝光，官方明确写成"获取与其服务不匹配的搜索展示位置"，处罚梯度到封号。**合规与搜索优化共用同一组红线**，所以先合规、再优化，顺序不能反。

## 三、功能设置规范（S1）

| 条款要点 | 自检表对应行 |
|---|---|
| 实际提供的服务和内容需与**简介一致**，且不存在隐藏类目 | 一致性行 |
| 核心功能必须在**首页**得到体现 | 首页行 |

## 四、搜索收录技术规则（S2/S3/S4/S5/S6/S7）

### 4.1 收录开关的三个层级

| 层级 | 位置 | 作用 |
|---|---|---|
| 全局开关 | 小程序管理后台 → 设置/功能 → **页面收录设置**（部分版本在「功能 → 页面内容接入 → 页面收录开关」） | 关闭则整个小程序不被索引 |
| sitemap 规则 | 项目根目录 `sitemap.json` | 对特定页面 allow / disallow |
| 主动推送 | `search.submitPages` 接口 | 提高对页面内容的收录量 |

### 4.2 sitemap.json 规则（来自 S5 官方社区原文）

```json
{ "rules":[{ "action": "allow", "page": "*" }] }
```
- 例1：所有页面都会被索引（默认情况）
- 例2：`{"action":"disallow","page":"path/to/page"}` → 该页不索引，其余允许
- 例3：先 allow 特定页，再 disallow 通配 → 只有特定页索引
- 例4：带 params 与 `"matching":"inclusive"` → 带指定参数的页面被**优先**索引

关键性质（来自 S5/S7）：
- **没有 sitemap.json 则默认所有页面都能被索引**
- `{"action":"allow","page":"*"}` 是**优先级最低**的默认规则，未显式 disallow 的都默认被索引
- 开发者工具控制台会显示当前页面是否被索引的调试信息（`project.config.json` → `setting.checkSiteMap` 可关）
- **sitemap 文件内容最大 5120 个 UTF8 字符**

### 4.3 三条"配了但没被收录"的坑（S4/S5 原文）

1. **web-view 组件中的任何内容不会被收录**（S4 第 5 条）。
2. 🔴 **若小程序爬虫发现的页面数据和真实用户的呈现不一致，那么该页面将不会进入索引中**（S5 官方社区原文）。
3. 索引不是即时的：配置提交后需等待，官方社区答复原文"提交后需要耐心等待，没有那么快显示数据的"（S6）。→ **当天改配置不当天下结论**。

### 4.4 页面标题与缩略图（S4 第 7 条）

- 页面标题和缩略图对搜索引擎理解页面和提高曝光有重要作用
- 通过 `wx.setNavigationBarTitle` 或自定义转发内容 `onShareAppMessage` 设置
- 为 `video`、`audio` 组件补齐 `poster` / `poster-for-crawler` 属性

### 4.5 路径推送（S4 第 8 条）

使用**页面路径推送能力**可提高平台对页面内容的收录量，进而提高曝光机会。

## 五、搜一搜结果的影响因素（S1/S4 公开口径）

官方公开表述中，搜索排名结果的主要影响因素：

1. **关键字匹配程度** —— 需提前了解核心用户群体常用的搜索词，并在**页面内容和小程序名称**中呈现
2. **用户侧行为** —— **使用过**该小程序、**好友使用过**，对搜索排名影响也很大
3. **页面收录质量** —— 页面结构清晰、加载规范、标题层级明确的页面优先收录
4. **违规过滤** —— 恶意 SEO、色情低俗、发布虚假内容的账号会被自动识别过滤，**封禁搜索能力**

> 🔴 **实务含义**：第 2 条（用户行为权重）说明纯靠改配置做搜索优化天花板有限——**收录是入场券，行为数据才是排序分**。所以"先合规、再收录、再用内容和体验拉行为数据"才是完整链路，本 Skill 前三段覆盖的是入场券这一段。

## 七、名称结构参考（来源为公开服务方经验整理，非官方规定）

以下结构在业内被普遍使用，但**不是微信官方规定**，属于"可用但不保证"的实践参考：

| 结构 | 示例 | 适用 |
|---|---|---|
| 地域 + 品类 + 品牌 | 成都烘焙·某某到家 | 本地服务、门店型 |
| 品牌 + 核心业务 | 某某生鲜商城 | 品牌已有认知 |
| 核心词 + 服务场景 | 社区团购自提商城 | 场景明确、直搜型 |

长度参考：业内经验称 4-30 字符区间，**实际以注册时后台提示为准**（这是〔待补〕项，必须用户在注册页确认）。

🔴 **不可用**的结构（与 S1 命名条款冲突）：
- 纯品类词（"短裤短裙"）
- 关键词串堆砌（"蛋糕面包烘焙甜品生日蛋糕千层慕斯商城"）
- 商业化前缀（"免费""清仓""巨便宜"）
- 极限词（"最便宜""第一""国家级"）
