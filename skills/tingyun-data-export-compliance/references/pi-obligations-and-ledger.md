# 个人信息出境额外义务、台账建法与供应商风险点

> 用途：解决"出境路径定了之后还要做什么""怎么建台账""供应商要问什么"三件事。
> 内容为清单与方法梳理，不构成法律专业意见，需人工复核。

## 一、个人信息出境相对普通数据出境的额外义务

只出境不含个人信息、不含重要数据的普通业务数据，走通路径即基本闭环。**含个人信息时**，以下每项都要单独过一遍，缺项就是缺口。

### 1.1 义务清单

| 编号 | 义务 | 具体内容 | 依据 | 常见缺口 |
|---|---|---|---|---|
| A1 | 告知 | 告知境外接收方名称、联系方式、处理目的、处理方式、个人信息种类、保存期限，以及个人行使权利的方式和程序 | 令第16号第十条；令第13号第五条 | 只告知"境外合作方"，未列名称与联系方式；保存期限写"按业务需要" |
| A2 | 单独同意 | 取得个人对出境事项的单独同意，不得以概括的服务协议或一揽子勾选带过 | 令第16号第十条 | 用注册协议整体同意代替单独同意；单独同意弹窗与实际出境场景不对应 |
| A3 | 个人信息保护影响评估 | 出境前完成，评估要点见 1.2 | 令第13号第五条；令第20号第六条 | 评估报告在出境之后补做；评估范围只覆盖一个系统，未覆盖关联链路 |
| A4 | 敏感个人信息专项说明 | 说明处理敏感个人信息的必要性以及对个人权益的影响 | 相关规定 | 只做单独同意，未做必要性说明；未识别哪些字段属于敏感个人信息 |
| A5 | 与境外接收方的法律文件 | 约定处理目的、方式、范围与安全保护义务；标准合同路径须按网信部门发布的范本文本订立，不得改动核心条款 | 令第11号第五条；令第13号第六条；条例第十二条 | 自拟"合作协议"替代标准合同；改动核心条款导致备案受阻 |
| A6 | 境外接收方履约能力评估 | 评估其承担义务的管理和技术措施、能力能否保障出境数据安全 | 令第13号第五条 | 只比对资质文件，未看实际安全措施与审计报告 |
| A7 | 出境后权益维护渠道 | 确保个人权益维护的渠道通畅 | 令第13号第五条 | 未指定响应窗口与时限，个人投诉无接收方 |
| A8 | 处理情况记录留存 | 提供、委托处理个人信息和重要数据的处理情况记录，至少保存3年 | 条例第十二条 | 无台账或只留近期一期数据 |
| A9 | 数量累计统计 | 自当年1月1日起按自然人计、跨链路合并统计 | 令第16号第七条、第八条 | 按系统分别统计，未合并；按记录条数而非自然人数 |

### 1.2 个人信息保护影响评估的六个重点

依据《个人信息出境标准合同办法》第五条，出境前开展个人信息保护影响评估，重点评估：

1. 个人信息处理者和境外接收方处理个人信息的目的、范围、方式等的合法性、正当性、必要性
2. 出境个人信息的规模、范围、种类、敏感程度，出境可能对个人信息权益带来的风险
3. 境外接收方承诺承担的义务，以及履行义务的管理和技术措施、能力等能否保障出境个人信息的安全
4. 出境后遭到篡改、破坏、泄露、丢失、非法利用等的风险，个人信息权益维护的渠道是否通畅
5. 境外接收方所在国家或者地区的个人信息保护政策和法规对标准合同履行的影响
6. 其他可能影响个人信息出境安全的事项

**写报告时的三个提示**：
- 每一项都要落到"我们做了什么"，不是"我们将会做"。写"将会"的部分在评估里等于没做
- 第 5 项不要跳过。境外接收方所在法域的个人信息保护制度差异，是评估结论里容易被漏掉的一段
- 报告要有版本与日期。链路规模或场景变了要出修订版，并说明变更点

### 1.3 敏感个人信息识别提示

常见敏感个人信息类别：生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹，以及不满十四周岁未成年人的个人信息。

处理敏感个人信息，除本表 A1~A9 外还须：取得单独同意（依规定需书面同意的另按要求执行）、说明处理的必要性以及对个人权益的影响。

**分档上的差别**：敏感个人信息单独计数，1万人以上即触到安全评估门槛；不满1万人落在标准合同/认证路径。这个数字单独算，不与普通个人信息合并。

## 二、数据分类分级与出境台账建法

### 2.1 分级的三层结构

| 层级 | 判定依据 | 出境时的处理逻辑 |
|---|---|---|
| 重要数据 | 被相关部门、地区告知，或被公开发布为重要数据；或行业重要数据识别指南已覆盖并经识别申报 | 须走数据出境安全评估；履行重要数据处理者义务（安全负责人与管理机构、年度风险评估报告等） |
| 个人信息 / 敏感个人信息 | 能否识别到自然人；是否涉及敏感类别 | 按累计人数分档，同时履行 A1~A9 |
| 一般数据 | 不含个人信息、不含重要数据 | 多数场景免于三条路径，但仍需履行数据安全保护义务 |

**实操建议**：先做字段级数据分类（每个数据表的每一列标注类别），再做数据集级归并。字段级做一次，表级归并就是汇总动作；反过来做会漏。

### 2.2 台账第 1 层：数据资产与分级台账（一行一类数据）

| 字段 | 填写要点 | 常见错误 |
|---|---|---|
| 数据标识 | 数据集名称、所属系统、业务归属、数据责任人 | 无责任人，后续无人可问 |
| 数据类别 | 个人信息 / 敏感个人信息 / 重要数据 / 一般数据，可多选 | 只标"个人信息"，未拆出敏感部分 |
| 是否已公开 | 已公开 / 未公开 | 漏填。已公开与未公开对重要数据判定影响明显 |
| 重要数据识别与申报状态 | 未识别 / 已识别未申报 / 已申报待认定 / 已被告知为重要数据 / 已被公开发布为重要数据 | 只填"未识别"却不说明是否按行业指南做过识别 |
| 规模 | 涉及自然人数、敏感个人信息人数、记录量级、数据量级 | 只填记录条数，不填自然人数 |
| 敏感程度 | 涉及哪几类敏感个人信息 | 填"含敏感信息"不写类别 |
| 存储位置 | 境内机房 / 境外区域 / 第三方机房（并注明第三方所在地） | 只写主库位置，漏备份与灾备 |
| 保留期限 | 存储期限与到期处理方式 | 空着 |

### 2.3 台账第 2 层：出境活动台账（一行一次出境行为）

| 字段 | 填写要点 |
|---|---|
| 链路编号 | 对应架构图或数据流图编号，能定位到具体链路 |
| 境外接收方 | 名称、所在法域、角色（受托处理方 / 共同处理方 / 独立处理方） |
| 出境目的与范围 | 具体到场景；不写"业务需要" |
| 传输形态 | 实时同步 / 批量导出 / 接口调用 / 远程登录 / 备份同步 |
| 频次与时间窗 | 同步频率、是否全量导出 |
| 数量累计 | 按自然人数、按敏感人数分别累计；标注统计起始日与统计口径 |
| 适用路径 | 落在哪一档；若走豁免，注明依据条款 |
| 完成状态 | 告知日期 / 单独同意日期 / 影响评估版本与日期 / 评估通过日期 / 标准合同订立与备案日期 / 认证状态，各自对应材料存放位置 |
| 有效期与复核 | 路径结果到期日、到期前复核责任人、复核记录 |
| 变更记录 | 场景、规模、接收方发生变化时的版本与审批 |

### 2.4 台账的三条使用规则

| 规则 | 说明 |
|---|---|
| 可回答 | 任取一天任一条链路，能立刻回答"当时怎么定的、谁批的、依据什么、现在还合不合规" |
| 可合并 | 数量统计必须跨链路合并。如果表是按系统分的，要另出一张跨系统的累计人数表 |
| 可举证 | 每一格都能指向一份具体材料的位置。填不出材料位置，说明这一格是推测而非记录 |

### 2.5 台账之外要单独建的两张表

| 表 | 内容 | 用途 |
|---|---|---|
| 数量累计统计表 | 按自然人数、按敏感人数，标注统计起始日与口径，跨链路合并 | 判断档位变化；发现档位迁移（如从不满10万人跨到10万人以上）时及时触发路径调整 |
| 有效期与复核台账 | 每条路径结果的到期日、复核责任人、复核结论 | 评估结果3年到期需在届满前60个工作日提出延长申请；标准合同与认证按各自规则管理 |

## 三、供应商与云服务的跨境风险点问询清单

采购与合同谈判阶段问清楚，比事后追要有效。以下问题建议逐条书面问，并要求书面答复。

### 3.1 数据位置与流向

| 编号 | 问询问题 | 追问点 |
|---|---|---|
| S1 | 主数据、备份、灾备、日志分别存储在哪些区域 | 四类分开问，常见情况是主库在境内、备份在境外 |
| S2 | 是否存在跨区域的备份同步或容灾复制 | 复制链路即出境链路 |
| S3 | 开发、测试、演示环境是否使用生产数据，副本存放在哪里 | 生产数据落入开发环境的比例高 |
| S4 | 是否存在数据抽样、标注、质检、人工审核的外包环节，地点在何处 | 数据标注外包常被漏掉 |

### 3.2 访问与运维

| 编号 | 问询问题 | 追问点 |
|---|---|---|
| S5 | 是否有境外人员登入生产环境或支持环境 | 关键在"可调取"，不在"看得到日志" |
| S6 | 境外运维的授权流程、审批记录、访问日志留存周期 | 无日志的境外访问，风险高 |
| S7 | 故障排查时是否会将数据导出到境外分析环境 | 排查工单与临时导出是常见通道 |
| S8 | 集团内部其他实体是否具有访问权限 | 关联公司访问权在合同里往往未写清 |

### 3.3 子处理者与分包

| 编号 | 问询问题 | 追问点 |
|---|---|---|
| S9 | 现有子处理者清单、所在地、职能 | 要清单，不要"我们都是自有团队" |
| S10 | 是否允许再分包 | 标准合同与法律文件对转委托有约束 |
| S11 | 子处理者变更的通知机制与提前期 | 没有提前期通知，实际就等于不可控 |
| S12 | 子处理者所在法域的政府调取请求披露实践 | 关系到履约能力评估 |

### 3.4 数据内容与遥测

| 编号 | 问询问题 | 追问点 |
|---|---|---|
| S13 | SDK 崩溃日志、埋点、性能监控数据上报到哪里 | 埋点常默认携带设备号、用户标识 |
| S14 | 遥测数据是否含用户标识、手机号、请求体内容 | 要看字段清单，不要看营销描述 |
| S15 | 工单系统部署位置，工单内容是否含用户数据 | 故障描述里常顺手贴用户标识 |
| S16 | 是否有第三方分析、客服、人工智能类服务接入，位置在何处 | 这类接入常绕过采购流程 |

### 3.5 合规状态

| 编号 | 问询问题 | 追问点 |
|---|---|---|
| S17 | 供应商自身在境内或境外是否承担出境义务，承担的是哪一档 | 供应商自己的合规结论不能覆盖你的责任 |
| S18 | 供应商是否有能力配合你的单独同意、告知、影响评估工作 | 配合能力决定你的义务能否落地 |
| S19 | 供应商的个人权利请求响应流程与时限 | 影响你的 A7 义务可执行性 |
| S20 | 供应商的安全认证与审计报告 | 用于境外接收方履约能力评估 |

### 3.6 合同里要写到的条款

| 条款 | 要点 |
|---|---|
| 处理目的、方式、范围 | 逐项列举，不用"业务需要"概括 |
| 安全保护义务 | 明确技术与管理措施，与影响评估结论对应 |
| 境外接收方履约能力 | 资质材料、安全认证、审计报告作为附件 |
| 再委托与共同处理 | 是否允许、需事先同意、责任如何划分 |
| 个人权利请求响应 | 响应窗口、时限、协助义务 |
| 审计与检查权 | 检查形式、频次、提前期 |
| 场景与规模变化的告知义务 | 触发条件、通知时限、配合重新判断的义务 |
| 数据泄露通知 | 通知时限（建议不迟于发现后24小时内启动通知）、通知内容、配合调查与补救义务 |
| 终止后的返还或删除 | 期限、证明文件要求 |
| 责任与赔偿 | 覆盖范围、与本地法定要求的衔接 |

## 四、把这张表变成可执行的节奏

| 频率 | 动作 | 产出 |
|---|---|---|
| 每次新增链路前 | 走出境判定 + 路径分档 + 自检清单 | 一条台账记录 + 一份自检勾选表 |
| 每月 | 更新数量累计统计表，检查是否跨档 | 累计人数表 + 是否触发路径调整的判断 |
| 每季度 | 核对有效期与复核台账 | 到期提醒清单 |
| 每年 | 复核数据分类分级台账；按行业重要数据识别指南复查识别与申报状态；复核重要数据处理者义务履行情况 | 分类分级复核记录、识别申报留痕、年度风险评估报告（涉重要数据时） |
| 变更发生时 | 场景、规模、接收方、字段变化 | 台账变更记录 + 路径是否需重新判断的结论 |
