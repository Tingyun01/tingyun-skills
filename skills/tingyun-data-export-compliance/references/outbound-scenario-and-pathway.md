# 出境情形判定与路径分档对照

> 用途：回答"这条链路算不算出境""落在哪一档"两件事。全部内容为路径框架梳理，不构成法律专业意见，需人工复核。
> 规则依据：《数据出境安全评估办法》（网信办令第11号，2022年7月7日公布，2022年9月1日施行）、《个人信息出境标准合同办法》（网信办令第13号，2023年2月22日公布，2023年6月1日施行）、《促进和规范数据跨境流动规定》（网信办令第16号，2024年3月22日公布施行）、《个人信息出境认证办法》（网信办、市场监管总局令第20号，2025年10月14日公布，2026年1月1日施行）、《网络数据安全管理条例》（国务院令第790号，2024年9月24日公布，2025年1月1日施行）、《数据出境安全评估申报指南（第三版）》（2025年6月）。

## 一、什么算数据出境：三种形态

依据《数据出境安全评估申报指南（第三版）》对出境行为的界定，下列情形属于数据出境行为：

| 序号 | 形态 | 判定要点 | 实务中的典型表现 |
|---|---|---|---|
| 1 | 境内运营中收集和产生的数据传输至境外 | 看数据是否出境落地 | 数据库同步到境外区域、文件导出后上传境外网盘、把境内数据写进境外 SaaS |
| 2 | 数据存储在境内，但境外机构、组织或者个人可以查询、调取、下载、导出 | 关键词是"可以" | 境外运维登入境内生产库查数据、境外客服后台可导出客户明细、境外总部有只读报表库 |
| 3 | 符合《个人信息保护法》第三条第二款情形，在境外处理境内自然人个人信息等其他数据处理活动 | 看处理行为发生在哪 | 境外研发团队用境内用户数据做分析、境外客服在境外工单系统里处理境内客户信息 |

**容易漏掉的两种情形**：
- **备份与灾备**：主库在境内、备份集同步到境外区域 → 属于形态 1
- **测试环境**：生产数据脱敏后落到境外测试环境 → 属于形态 1；未脱敏直接落境外 → 同时涉及形态 1 与个人信息处理问题

**不构成数据出境的常见情形**（仍需保留判断留痕）：

| 情形 | 说明 | 需留存 |
|---|---|---|
| 境外只获取不可回溯到个人的聚合统计 | 指标粒度已到无法通过任何方式关联到个人 | 去标识化处理方法说明、技术不可重识别验证、样本量与精度控制记录 |
| 境外个人因私访问其自身在境外合法获取的数据 | 与境内数据处理者无关 | 主体身份与数据来源合法性说明 |
| 境内数据处理者仅向境外提供不含个人信息与重要数据的普通业务数据 | 如设备运行统计、无关个人的物料编码 | 数据字段清单与判定说明 |

**不构成出境的错误理由**（这几条都不能作为依据）：

| 错误理由 | 为什么站不住 |
|---|---|
| "数据加密了" | 加密不改变数据是否出境，只改变泄露后的可读性 |
| "用的是专线 / VPN" | 通道形式不改变定性 |
| "量很小" | 量小只影响落在哪一档，不影响是否出境 |
| "对方是关联公司 / 集团内部门" | 关联关系不构成豁免依据，反而牵出法律文件约定的必要性 |
| "只给管理员看，没给业务看" | 境外可查询、可调取即可落入形态 2，权限大小不影响定性 |
| "只做统计不存明细" | 若统计口径可回溯到个人，属于个人信息处理，需判断匿名化是否成立 |

## 二、豁免闸门：命中任一即免于申报评估、订立标准合同、通过认证

依据《促进和规范数据跨境流动规定》第三条至第六条、《网络数据安全管理条例》第三十五条：

| 编号 | 豁免情形 | 条款出处 | 判定要点 | 需留存 |
|---|---|---|---|---|
| 1 | 国际贸易、跨境运输、学术合作、跨国生产制造和市场营销等活动中收集和产生的数据向境外提供，不包含个人信息或者重要数据 | 令第16号第三条 | 活动类型 + 数据内容两项都要成立 | 活动类型说明、字段级数据分类说明 |
| 2 | 境外收集和产生的个人信息传输至境内处理后向境外提供，处理过程中没有引入境内个人信息或者重要数据 | 令第16号第四条 | "处理过程中未引入"是关键 | 境内处理环节的数据来源说明、技术隔离与不可回写证明 |
| 3 | 为订立、履行个人作为一方当事人的合同所必需（如跨境购物、跨境寄递、跨境汇款、跨境支付、跨境开户、机票酒店预订、签证办理、考试服务等） | 令第16号第五条第（一）项 | 必须是"必需"，非必需的部分不豁免 | 必要性说明：业务场景与该数据字段的对应关系 |
| 4 | 按照依法制定的劳动规章制度和依法签订的集体合同实施跨境人力资源管理所必需，向境外提供员工个人信息 | 令第16号第五条第（二）项 | 限于员工个人信息，需有制度依据与集体合同依据 | 劳动规章制度、集体合同、员工告知与单独同意记录 |
| 5 | 紧急情况下为保护自然人的生命健康和财产安全所必需 | 令第16号第五条第（三）项 | 紧急状态与必要性 | 紧急事件记录、必要性判断说明 |
| 6 | 关键信息基础设施运营者以外的数据处理者，自当年1月1日起累计向境外提供不满10万人个人信息（不含敏感个人信息） | 令第16号第五条第（四）项 | 人数按自然人计、跨链路累计 | 累计人数统计表与口径说明 |
| 7 | 自由贸易试验区负面清单外的数据向境外提供 | 令第16号第六条 | 需在自贸区内，且有经批准的负面清单 | 适用自贸区负面清单的核查记录 |

**注意**：以上所称向境外提供的个人信息，不包括重要数据。个人信息豁免不等于重要数据豁免。

## 三、分档表：身份 + 数据类型 + 累计人数三维判断

判断顺序：**先确认身份**（是否关键信息基础设施运营者）→ **再确认数据类型**（是否含重要数据、是否敏感个人信息）→ **再算累计人数** → **再过豁免闸门**（闸门命中优先）。

### 3.1 身份与数据规模分档（令第16号第七条、第八条）

| 情形 | 路径 | 依据 |
|---|---|---|
| 关键信息基础设施运营者向境外提供个人信息或者重要数据 | 申报数据出境安全评估 | 令第16号第七条第（一）项 |
| 非关基运营者向境外提供重要数据 | 申报数据出境安全评估 | 令第16号第七条第（二）项 |
| 非关基运营者自当年1月1日起累计向境外提供100万人以上个人信息（不含敏感个人信息） | 申报数据出境安全评估 | 令第16号第七条第（二）项 |
| 非关基运营者自当年1月1日起累计向境外提供1万人以上敏感个人信息 | 申报数据出境安全评估 | 令第16号第七条第（二）项 |
| 非关基运营者自当年1月1日起累计向境外提供10万人以上、不满100万人个人信息（不含敏感个人信息） | 订立个人信息出境标准合同，或通过个人信息保护认证 | 令第16号第八条 |
| 非关基运营者自当年1月1日起累计向境外提供不满1万人敏感个人信息（且未达上述评估门槛） | 订立个人信息出境标准合同，或通过个人信息保护认证 | 令第16号第八条 |
| 非关基运营者自当年1月1日起累计向境外提供不满10万人个人信息（不含敏感个人信息） | 免于申报评估、订立标准合同、通过认证 | 令第16号第五条第（四）项 |

### 3.2 "不满100万人"这条限制的作用

《个人信息出境标准合同办法》第四条的适用条件包含"处理个人信息不满100万人"；《数据出境安全评估办法》第四条把"关键信息基础设施运营者和处理100万人以上个人信息的数据处理者向境外提供个人信息"列入评估申报情形。两条合起来看：

- 处理个人信息不满100万人，且当年累计出境人数在10万人以上不满100万人 → 标准合同 / 认证路径
- 处理个人信息达到100万人以上 → 触到评估口径，属于令第16号第七条第（二）项情形（当年累计出境100万人以上个人信息）

**边界情形**：处理总量不满100万人，但当年累计出境人数达到100万人 → 落入令第16号第七条第（二）项"累计向境外提供100万人以上个人信息"，应走评估路径。

### 3.3 数量口径四条硬规则

| 规则 | 内容 | 出处 |
|---|---|---|
| 统计起点 | 自当年1月1日起累计 | 令第16号第七条、第八条；令第20号第五条 |
| 计数单位 | 按自然人计，不按记录条数 | 同上 |
| 合并统计 | 多条链路、多套系统向同一境外接收方提供个人信息，人数合并累计 | 实践口径要求 |
| 禁止拆分 | 不得采取数量拆分等手段，把依法应当通过出境安全评估的个人信息通过订立标准合同或通过认证方式向境外提供 | 《个人信息出境标准合同办法》第四条；《个人信息出境认证办法》第五条 |

### 3.4 三条路径的硬性动作对照

| 维度 | 数据出境安全评估 | 个人信息出境标准合同 | 个人信息保护认证 |
|---|---|---|---|
| 适用身份 | 关基运营者；非关基运营者出境重要数据或达数量门槛 | 非关基运营者，处理个人信息不满100万人，达10万人/1万人门槛 | 与标准合同路径同档，二选一 |
| 前置动作 | 申报前完成数据出境风险自评估 | 出境前完成个人信息保护影响评估 | 出境前完成告知、单独同意、影响评估 |
| 核心文件 | 申报书、数据出境风险自评估报告、与境外接收方拟订立的法律文件、安全评估工作需要的其他材料 | 标准合同（按网信部门发布的范本文本，不得改动核心条款）+ 个人信息保护影响评估报告 | 认证申请材料，由具备相应资质的专业认证机构开展 |
| 办理去向 | 通过所在地省级网信部门向国家网信部门申报；线上可通过数据出境申报系统提交 | 标准合同生效之日起10个工作日内向所在地省级网信部门备案 | 按认证规则向认证机构申请 |
| 结果有效期 | 3年，自评估结果出具之日起计算；届满前60个工作日内可申请延长，获批延长3年 | 按合同与备案要求管理 | 按认证规则与证书载明 |
| 结果边界 | 不得超出评估明确的目的、方式、范围、种类、规模 | 不得超出合同与备案载明的范围 | 不得超出认证范围 |

### 3.5 重要数据的判定处理

《促进和规范数据跨境流动规定》第二条规定：数据处理者应当按照相关规定识别、申报重要数据。未被相关部门、地区告知或者公开发布为重要数据的，数据处理者不需要作为重要数据申报数据出境安全评估。

《网络数据安全管理条例》第二十九条：国家数据安全工作协调机制统筹协调有关部门制定重要数据目录；各地区、各部门应当确定本地区、本部门及相关行业、领域的重要数据具体目录。数据处理者应当按照国家有关规定识别、申报重要数据；对确认为重要数据的，相关地区、部门应当及时向数据处理者告知或者公开发布。

《网络数据安全管理条例》第三十七条：数据处理者按照国家有关规定识别、申报重要数据，但未被相关地区、部门告知或者公开发布为重要数据的，不需要将其作为重要数据向境外提供（据其上下文，重要数据出境应当通过数据出境安全评估）。

**实务处理建议**：
1. 先查本行业、本领域是否已有公开的重要数据识别指南或申报规则（如工业、电信、自然资源、统计等领域已发布相关文件）
2. 按指南完成识别与申报，保留全流程记录
3. 若已被告知或公开发布为重要数据 → 出境须走安全评估，并按《网络数据安全管理条例》第三十条、第三十二条履行相应义务（如设立网络数据安全负责人与管理机构、年度风险评估报告等）
4. 若未覆盖且未被告知 → 依令第16号第二条处理，但仍应做好识别申报留痕，以备核查

### 3.6 自贸区负面清单

令第16号第六条：自由贸易试验区在国家数据分类分级保护制度框架下，可以自行制定区内需要纳入数据出境安全评估、个人信息出境标准合同、个人信息保护认证管理范围的数据清单，经省级网信部门批准后报国家网信部门、国家数据管理部门备案。区内数据处理者向境外提供负面清单外的数据，可以免予申报评估、订立标准合同、通过认证。

**核对动作**：企业是否注册在自贸区内（不是业务在自贸区就算）；负面清单的批准与备案状态；本条链路数据是否落入清单内。
