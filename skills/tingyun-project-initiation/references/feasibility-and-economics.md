# 四维可行性自检与投入产出测算

## 一、四维自检表（逐维填写）

每一维填五列：**自检问题 / 现有证据 / 证据是否充分 / 不成立信号 / 待补动作**。
证据不充分这一维，结论栏写"未完成"，不要写"通过"。

### 1.1 技术维

| 自检问题 | 现有证据 | 充分 | 不成立信号 | 待补动作 |
|---|---|---|---|---|
| 关键技术是否已被验证过 | 原型/测试报告/先前项目 | 有可复现的验证结果 | 只有设想，无任何验证 | 做打通关键链路的原型 |
| 关键技术难度属于哪一类 | 团队评估 | 能区分"成熟方案"与"需突破" | 说不清难度等级 | 找做过同类方案的团队评审 |
| 核心团队是否有同类经验 | 履历与项目记录 | 有可比项目 | 核心成员零经验且无备份 | 补关键岗位或外部顾问 |
| 依赖的外部能力是否稳定 | 依赖说明与供方承诺 | 有书面确认 | 依赖单点且不可替换 | 做双方案或备选路径 |
| 性能、容量、稳定性指标 | 技术方案 | 指标可测且有目标值 | 无量化指标 | 补技术指标表 |
| 数据与系统基础是否具备 | 数据盘点、系统清单 | 现状清楚 | 不知道要接哪些系统 | 做数据与接口盘点 |
| 技术债与遗留系统耦合 | 影响评估 | 影响范围已识别 | 说不清影响面 | 做影响面清单 |
| 后续维护与迭代成本 | 估算 | 有粗略量级 | 完全未考虑 | 补运维成本条目 |

### 1.2 市场维

| 自检问题 | 现有证据 | 充分 | 不成立信号 | 待补动作 |
|---|---|---|---|---|
| 需求是否真实存在 | 访谈纪要、行为数据 | 来自目标用户非熟人 | 样本全是熟人或内部推演 | 补充外部样本访谈 |
| 客户是否愿意付钱或改变行为 | 付费、预付、试点 | 有付费或行为改变证据 | 只有口头兴趣 | 设计小额付费试点 |
| 需求强度与频次 | 分层测算 | 有分层与频次 | 把所有潜在用户当目标 | 做客户分层 |
| 市场容量是否支撑目标 | 自上而下 + 自下而上两套 | 两套口径能对上 | 只有一套乐观口径 | 做两套测算并说明差异 |
| 替代方案与竞争 | 竞品与替代路径分析 | 覆盖直接替代与"什么都不做" | 只看直接竞品 | 补替代方案分析 |
| 获客与转化路径 | 渠道测算 | 有渠道与转化率依据 | 转化率凭感觉 | 做小规模投放测试 |
| 复购与留存假设 | 历史同类数据 | 有可类比数据 | 首次转化当长期留存 | 补留存假设与验证 |
| 需求会变吗 | 趋势与政策观察 | 有判断与应对 | 假定需求稳定十年 | 写明需求变化时的调整口径 |

### 1.3 资源维

| 自检问题 | 现有证据 | 充分 | 不成立信号 | 待补动作 |
|---|---|---|---|---|
| 人力从哪来 | 人力盘点与缺口表 | 来源明确 | 关键岗位靠临时协调 | 明确内部调配或招聘计划 |
| 关键角色的投入时段 | 部门书面确认 | 有书面确认 | 只有口头支持 | 走正式确认流程 |
| 预算来源与可支配性 | 预算批复或额度证明 | 来源可查 | 预算来源不明 | 确认预算科目 |
| 外部依赖方是否配合 | 供方/合作方书面反馈 | 有书面确认 | 依赖口头承诺 | 争取书面确认并设风险 |
| 关键资源是否可替换 | 替代方案分析 | 关键资源有备份 | 单点资源（只有一人掌握的关键技能、只有一台的专用设备） | 培养备份或外部采购 |
| 管理与决策支持 | 决策链条与授权 | 决策路径清楚 | 没人拍板 | 明确决策人与时间 |
| 时间窗口与资源冲突 | 资源占用冲突分析 | 冲突已识别 | 与在跑项目撞资源 | 排优先级并调整 |
| 合规与前置许可 | 合规口径与许可清单 | 结论明确 | 前置许可未确认 | 咨询合规并出清单 |

### 1.4 财务维

| 自检问题 | 现有证据 | 充分 | 不成立信号 | 待补动作 |
|---|---|---|---|---|
| 投入项是否完整 | 测算表 | 含直接与间接成本 | 只算了外采与设备 | 补内部工时与机会成本 |
| 收益项怎么算出来的 | 测算表与参数来源 | 每个参数有来源 | 收益用比例拍脑袋 | 逐参数标注来源 |
| 是否有情景分析 | 三档情景 | 有悲观/中性/乐观 | 只有一个数字 | 补情景表 |
| 是否有敏感性分析 | 敏感度排序 | 找出敏感度排在前列的参数 | 未做 | 做单参数敏感性 |
| 回收期与回本节奏 | 测算结果 | 有月份与拐点 | 只算总额 | 补逐年现金流 |
| 一次性投入的摊销口径 | 摊销表 | 写明摊几年摊多少量 | 隐含忽略 | 补摊销明细 |
| 沉没成本与退出成本 | 估算 | 有量级 | 未考虑 | 补退出成本条目 |
| 与替代方案比过吗 | 对比测算 | 有可比口径 | 未对比 | 补方案对比 |

### 1.5 四维汇总

| 维度 | 结论（通过 / 未完成 / 不成立） | 关键缺口 | 补齐动作与责任人 | 补齐期限 |
|---|---|---|---|---|
| 技术 | | | | |
| 市场 | | | | |
| 资源 | | | | |
| 财务 | | | | |

**汇总判据**：
- 四维中有两维及以上"不成立" → 现阶段不建议推进；
- 任一维度"未完成"且缺口涉及关键假设 → 先补验证动作，再进评审；
- 四维均通过 → 进评审，但仍需第四节的止损设计兜底。

## 二、投入产出测算框架

### 2.1 投入项清单（每一项要落到人和时间）

| 投入项 | 计量口径 | 取值 | 来源 | 一次性/经常性 | 归属期间 |
|---|---|---|---|---|---|
| 内部人力 | 人天 × 内部成本率 | | 人力台账 / 预算口径 | 一次性+经常性 | 按阶段分摊 |
| 外部采购（软件/硬件/服务） | 合同额 | | 报价 | 一次性 | 采购节点 |
| 外包与外部人力 | 合同额或人天 | | 报价 | 经常性 | 按月/按阶段 |
| 场地与设备 | 占用费 / 折旧 | | 内部台账 | 经常性 | 按月 |
| 系统改造与集成 | 工作量 × 内部成本率 | | 评估 | 一次性 | 改造阶段 |
| 培训与变更管理 | 人天 × 成本率 | | 计划 | 一次性 | 上线前 |
| 物料与试制 | 批次成本 | | 试制记录 | 一次性 | 试点阶段 |
| 认证与合规成本 | 咨询与评审费 | | 报价 | 一次性 | 立项后 |
| 机会成本 | 被占用的资源本可产生的收益 | | 管理层口径 | 经常性 | 全周期 |
| 维护与运维 | 年度 | | 运维方案 | 经常性 | 上线后 |
| 风险准备金 | 按风险清单估算 | | 风险评估 | — | 备用 |

**判据**：投入项里如果只有"外部采购"和"设备"，说明测算漏了内部人力与机会成本——这两项在内部立项里经常是占比排在前列的两项。

### 2.2 收益项清单（分四类，来源强度递减）

| 收益类型 | 计量方式 | 证据要求 | 常见夸大方式 | 修正做法 |
|---|---|---|---|---|
| 新增收入 | 客户数 × 客单价 × 转化率 × 复购率 | 渠道测试数据 + 同类历史值 | 用满产假设、漏爬坡期 | 加爬坡曲线：按月产能爬坡表 |
| 成本节省 | 原流程成本 − 新流程成本 | 现状成本台账 | 只算节省不减新增维护 | 把新增运维成本计入同口径 |
| 风险规避 | 发生概率 × 影响金额 | 历史事故与敞口数据 | 概率拍脑袋、金额取上限 | 给区间并写明概率依据来源 |
| 效率与体验提升 | 折算工时或转化率提升 | 工时记录或对比测试 | 把理论工时全额算作现金收益 | 按"人力实际释放并被重新配置"的比例折算 |

**关键提醒**：不是所有"节省"都是收益。**节省下来的工时如果没有被重新配置到其他产出上，它只是一项成本下降，不是现金收益。**在测算表里单列一行"释放工时的再配置去向"，写不出来就把这一项收益按折扣计入。

### 2.3 测算结果表（可复算结构）

```
【时间轴】按月或按季展开，与里程碑对齐
月份：   M1    M2    M3    M4    M5    M6    M7    M8   ...   M12

收入：                                    R1    R2   ...
成本节省：                                       S1   ...
净现金流： = 收入 + 节省 − 投入
累计净现金流：
回收月： 第 __ 月（累计净现金流转正的月份）
```

| 总投入 | 各期投入合计 | | | |
| 总收益（12/24/36 个月） | 各期收益合计 | | | |

**可信度标注规则**：有实测数据或有书面报价支撑的标"高"；有同类历史值可参照的标"中"；纯经验估计标"低"。**标"低"的参数要单独列出，并说明它进入敏感性排名的位置。**

### 2.5 敏感性分析（单参数）

逐个参数取悲观值，看净额变化，按影响幅度排序：

| 参数 | 中性取值 | 悲观取值 | 净额变化幅度 | 排序 | 缓解动作 |
|---|---|---|---|---|---|
| 转化率 | | | | | |
| 爬坡周期 | | | | | |
| 内部人力成本 | | | | | |
| 外部采购单价 | | | | | |
| 项目周期延长 | | | | | |

**判据**：如果排在首位的参数波动 ±30% 就让项目从赚变亏，那这个项目**本质上是在赌这一个参数**。这时候正确的做法不是把数字调好看，而是**先花小成本把这个参数测准**（做渠道测试、做原型验证）。

## 三、高估点对照清单（自查用）

| # | 高估位置 | 典型表现 | 真实风险 | 修正动作 |
|---|---|---|---|---|
| 1 | 收入按满产算 | 当年就达稳态产能 | 现金断档，中途停摆 | 做月度爬坡曲线，首年按爬坡期收入算 |
| 2 | 漏算内部成本 | 只算外采与设备 | 后期追加预算，突破已批额度 | 补内部人力按人天计、含机会成本 |
| 3 | 周期估得乐观 | 按理想排期倒推 | 每个环节延误会串行放大 | 按历史同类项目的实际耗时校准，加缓冲 |
| 4 | 没有悲观情景 | 只有一个数字 | 上会时无法回答"如果不行呢" | 强制三档情景 |
| 5 | 收益按毛额算 | 节省全额计为收益 | 收益虚高，投入产出比失真 | 新增成本同口径计入，释放工时打折 |
| 6 | 摊销与固定成本隐含忽略 | 一次性投入直接摊进单月 | 单月现金流虚高 | 写明摊销年限与摊销量 |
| 7 | 风险规避收益凭感觉 | 概率与金额都是拍的 | 评审一问就露 | 给区间与依据，或不计入基准情景 |
| 8 | 忽略变更与返工 | 按一次做对设计 | 返工成本吃掉全部缓冲 | 在周期里预留返工比例 |
| 9 | 把"资源已投入"当"投入有价值" | 已花的钱算进未来收益 | 论证被历史投入绑架 | 评审只看未来现金流，历史投入单列 |
| 10 | 汇总时遗漏一项 | 各表数字对不上 | 评审无法复算 | 三张表交叉核对，差额说明 |

**判据：以上十条逐条自查，凡命中且未做修正的，在评审材料里显式写出来**（"本测算采用满产假设，爬坡期已按 6 个月建模"）。**主动说明的假设通常不会被否，藏起来的假设一定会被问出来。**

## 四、测算结论的写法

测算表末尾要有一段结论，结构固定：

```
【结论】
测算口径：按 ____ 个月周期，____ 情景假设
中性情景：总投入 ____，总收益 ____，回收期第 ____ 月，投入产出比 ____
悲观情景：总投入 ____，总收益 ____，回收期 ____（无 / 第 ____ 月）
关键假设排序（敏感度）：1 ____  2 ____  3 ____
结论类型：□ 具备推进条件  □ 需先验证假设 ____  □ 不建议推进
本次请评审决策的事项：□ 通过并释放首阶段预算 ____  □ 附条件通过（条件：____）
下阶段预算释放额度与触发条件：____
```

**判据**：结论段里必须有"本次请评审决策的事项"和"下阶段预算释放额度与触发条件"两行。**没有这两行，这份材料就不是一个决策文件，而是一份汇报材料——评审会无从下手，只能给一个模糊的态度。**
