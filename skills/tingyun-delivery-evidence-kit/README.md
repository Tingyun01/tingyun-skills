# tingyun-delivery-evidence-kit

> 交付时自动生成交付清单、件数核对、校验值与版本时间戳，让买家能自证、卖家能少纠纷
>
> 面向卖虚拟资料、模板与服务的个体卖家和小商家的交付履约工具。在每次交付时自动生成交付清单，逐项列出文件、页数与条目数，附校验值、版本号与交付时间戳，并生成买家确认页与合规退换规则文本，把承诺与交付变成可核对的数字，减少因无法举证而起的退款与纠纷。

## 这个 Skill 做什么

把「数字交付证据」这个场景最容易出错、也最没人负责的环节，拆成**可执行的判断步骤 + 检查清单 + 固定输出格式**。
你给案情/材料，它输出该问什么、该查什么、该准备什么、风险点在哪。

### 解决什么问题

虚拟商品卖家的真实成本，往往不在纠纷本身，而在**举证不能**。买家拿到手说"跟你说的不一样"，卖家翻遍聊天记录只能回一句"我发给你的就是这个"，双方都拿不出可核对的东西，最后平台按"虚拟商品无有效证明"处理：卖家退款，买家骂人，下一个买家继续担心。

虚拟商品投诉里有一批反复出现的共同根因——**买家收到货后无法证明卖家给的和说的一致**。买家最常见的说法是：

- "24章节的内容只有6章" → 缺件数核对

- "口诀只有35条，剩下的以其他资料滥竎充数" → 缺条数核对

- "重点加上习题一共就30页，只列问题让自己整理答案" → 缺交付形态说明

- "商品采用网盘链接自动发货，但详情页没有显著提前告知必须使用百度网盘才能下载" → 缺前置条件告知

## 什么时候会触发

当你要处理以下事情时，这个 Skill 会被自动激活：

- 买家说收到的资料和描述不一样怎么办
- 我怎么证明我给的东西是完整的
- 卖资料老是被人投诉退款
- 怎么写一个买家不会说货不对板的交付说明

## 怎么用

1. 安装到你的 agent（Claude Skills 目录 / 扣子技能商店）
2. 直接用日常说法提需求，例如：
   买家说收到的资料和描述不一样怎么办
3. 它会追问关键信息（缺的信息会标〔待补〕，不会替你编）
4. 输出可直接用的清单 / 对照表 / 台账

## 输出

- 判断步骤与检查清单
- 对照表 / 台账
- 待办与需要人工核实的问题

## 边界

- 不构成法律 / 税务 / 医疗专业意见，最终判断需人工复核
- 遇到需要执业资格才能定论的问题，它会明确说"建议转专业机构"
- 单次购买、单人授权使用；**不可转售或再分发**

## 许可

原创方法论整理，仅供个人工作流使用。不得转售、再分发或作为商品二次售卖。
