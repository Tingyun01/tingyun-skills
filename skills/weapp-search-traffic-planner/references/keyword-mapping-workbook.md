## 表 B · 关键词-页面对应表（决定"搜什么词、从哪个页面被搜到"）

### B-1 词库分级

| 词 | 词级（核心/场景/长尾） | 搜索意图（找功能/找地域/找品牌/找价格） | 放在哪个位置（名称/简介/页面标题） | 是否与服务强相关 | 备注 |
|---|---|---|---|---|---|
| | | | | | |
| | | | | | |

**分级规则**
- **核心词** → 名称（权重高，但全局唯一且难改，一个都别浪费）
- **场景词** → 简介（补充 2-3 个，覆盖不同搜索意图）
- **长尾词** → 页面标题（一个页面对应一个搜索意图，不要所有页面共用"首页"标题）

**词级判定卡**
| 词型 | 特征 | 竞争 | 建议 |
|---|---|---|---|
| 通用短词 | "减肥""生鲜" | 极高，正面对撞品牌 | 慎用，容易被堆砌判定 |
| 长尾场景词 | "减肥食谱一周瘦10斤""社区团购自提" | 低 | **首选切入点**，转化率高 |
| 地域词 | 城市名+品类 | 中 | 本地服务必配 |
| 品牌词 | 自有品牌 | 极低 | 始终留一个位置 |

🔴 **红线**：词库里凡是为了蹭流量而加的、与实际服务无关的词，一律不得进入本表——S1 命名条款明文禁止"堆砌热门搜索词或与自身服务无关的关键词"。

### B-2 关键词 → 落地页对应

| 搜索词 | 落地页路径 | 该页标题格式（核心关键词+品牌名） | 该页必须包含的内容要素 | 是否需推送收录 |
|---|---|---|---|---|
| | | | | |
| | | | | |

**标题格式规则**：每个页面独立标题，格式为「核心关键词 + 品牌名」。**禁止所有页面共用「首页」统一标题**——那样等于放弃了长尾词的落地页。

## 表 C · 收录配置清单（解决"配了但没被收录"）

### C-1 sitemap.json 模板

**默认（全站可索引，仅屏蔽低价值页）**
```json
{
  "rules": [
    { "action": "disallow", "page": "pages/privacy/index" },
    { "action": "disallow", "page": "pages/log/index" },
    { "action": "allow", "page": "*" }
  ]
}
```

**精确控制（只索引核心落地页）**
```json
{
  "rules": [
    { "action": "allow", "page": "pages/detail/index" },
    { "action": "allow", "page": "pages/category/index" },
    { "action": "disallow", "page": "*" }
  ]
}
```

**带参数优先索引**
```json
{
  "rules": [
    { "action": "allow", "page": "pages/detail/index", "params": ["id"], "matching": "inclusive" },
    { "action": "allow", "page": "*" }
  ]
}
```

**填入你的配置**
```json
{
  "rules": [

  ]
}
```

**规则提醒**
- 没有 sitemap.json → 默认全部可索引
- `{"action":"allow","page":"*"}` 优先级最低，未显式 disallow 的都默认被索引
- 文件上限 5120 个 UTF8 字符

### C-2 需推送页面 / 需屏蔽页面

| 页面路径 | 收录决策 | 理由 |
|---|---|---|
| | allow / disallow / push | |

**屏蔽原则**：隐私政策页、登录后个人页、订单详情页、无搜索价值的中间页 → disallow
**推送原则**：核心落地页、品类列表页、内容详情页 → `search.submitPages` 主动推送

### C-3 爬虫一致性三条核查（每条要收录的页面逐条过）

| # | 核查项 | 怎么查 | 通过标准 |
|---|---|---|---|
| K1 | **用户看到的和爬虫抓到的是不是同一份内容** | 抓取预览 vs 用户实际浏览对比 | 一致 |
| K2 | **是不是 web-view 页面** | 看页面结构是否 `<web-view>` | 不是 web-view（web-view 内容不被收录） |
| K3 | **有没有独立标题和缩略图** | 检查 `wx.setNavigationBarTitle` / `onShareAppMessage`；`video`/`audio` 是否补 `poster`、`poster-for-crawler` | 都有 |

🔴 K1 是最容易踩的一条：爬虫看到的与用户看到的不一致 → 该页**直接不进索引**，且平台不会告诉你原因。

### C-4 索引验证与观察排期

| 检查项 | 时点 | 结果 | 〔待补〕 |
|---|---|---|---|
| 微信后台 → 页面内容接入 → 收录概况 | 配置后 ≥3 天 | | 〔待补〕 |
| 微信后台 → 页面内容接入 → 整体数据 | 配置后 ≥3 天 | | 〔待补〕 |
| 搜一搜实搜品牌词 | 配置后 ≥3 天 | 排名位置 | 〔待补〕 |
| 搜一搜实搜 1-2 个长尾词 | 配置后 ≥3 天 | 排名位置 | 〔待补〕 |

> 🔴 **官方社区原话：提交后需要耐心等待，没有那么快显示数据。** → **当天改配置不当天下结论**，观察窗口至少 3 天。
