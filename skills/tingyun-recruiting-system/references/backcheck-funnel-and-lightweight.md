# 背调核查、招聘漏斗诊断与轻量招聘方案

配套专家包：tingyun-recruiting-system（招聘流程与面试评价顾问）

本文件提供核查清单、漏斗诊断表、轻量流程方案与 JD 写法要点。所有内容为一般性参考。

本文件仅为招聘流程设计参考，不构成法律专业意见，需人工复核。涉及候选人个人信息处理、背景调查合规、录用通知效力、劳动合同与试用期约定的事项，请转交公司法务或执业律师处理。

## 一、背调与入职前核查

### 1.1 核查前的两个前置动作

| 前置动作 | 要求 | 边界提示 |
|---|---|---|
| 取得授权 | 候选人**书面授权**后方可开展核查与联系其前雇主 | 个人信息处理与背调的合规口径须由公司法务或律师复核 |
| 告知用途与范围 | 明确核查哪些项、用于何处、保存多久 | 同上，属需专业复核事项 |

本包只给流程动作提示，**不提供**个人信息处理合法性、查询渠道合规性、录用通知效力等法律层面的结论。这类事项一律转专业口复核。

### 1.2 常规核查项清单

| 核查项 | 常规内容 | 与岗位的相关性原则 | 需注意 |
|---|---|---|---|
| 身份 | 身份信息与本人一致 | 高 | 需本人提供材料或授权查询 |
| 学历学位 | 学历、学位、学校、专业 | 中 | 核查渠道的合法性需确认 |
| 执业资格 | 与岗位相关的资格证书、注册状态 | 高（特定岗位） | 造假处理需事先写入录用条件 |
| 任职履历 | 任职公司、职位、起止时间 | 高 | 只核对与岗位相关的事实 |
| 离职原因 | 前雇主口径的一句话说明 | 中 | 不追问健康、家庭等私人原因 |
| 工作表现与推荐 | 前直属上级的推荐反馈 | 中 | 需授权后联系，问题限于工作表现 |
| 竞业与保密 | 是否存在相关限制 | 高（技术/销售岗） | 与公司已有协议的衔接需法务确认 |

### 1.3 核查提问的边界

向候选人前雇主或推荐人提问时：

- 只问与岗位相关的工作事实（职责、协作方式、工作产出的大致水平）。
- 不问与岗位无关的私人信息（家庭、婚育、健康、年龄）。
- 不诱导负面评价（例如"他是不是不太靠谱"这类问题不能问）。
- 记录原话，不做推断；不清楚就写"不清楚"。

判断原则：**这个问题与"能不能胜任这个岗位"有没有可说明的关联**。没有，就不问。

### 1.4 入职前组织流程清单（不涉及候选人隐私）

- [ ] 录用通知的关键信息已书面确认：岗位、薪酬构成、报到时间、试用期约定
- [ ] 候选人对**薪酬构成的各部分**有明确理解（固定 / 浮动 / 长期激励），理解一致宜留一条书面回复
- [ ] 报到日期、材料清单、办理时间点与责任人已明确告知
- [ ] 用人部门已拿到岗位画像与胜任力模型，便于入职后对齐期望
- [ ] 试用期目标、考核方式与时间点已提前沟通
- [ ] 需签署的协议清单已列出，签署时间与流程已安排
- [ ] 背景核查的授权文件已备（如做核查）
- [ ] 薪酬发放、社保公积金等手续的办理时间与责任人已明确
- [ ] 入职前 3~5 天的联系节奏已安排（减少 offer 后失联）
- [ ] 团队内部已同步到岗信息（谁带、坐在哪、首日做什么）

### 1.5 候选人体验的常见扣分项

| 扣分项 | 表现 | 修法 |
|---|---|---|
| 流程不透明 | 不知道还有几轮、要等多久 | 邀约时一次说清轮次、时长、反馈时间 |
| 反复改时间 | 面试改期两次以上 | 一次性确认可用时段 |
| 长时间无反馈 | 面完两周没消息 | 定反馈时限，超时也要给一句告知 |
| 面试官不专业 | 迟到、临时改题、只让候选人讲项目不讲角色 | 面前列本轮主问题与分工 |
| 信息不对称 | 到临签前才告知薪资结构 | 流程开始时就说清薪酬结构与区间 |

## 二、招聘漏斗流失诊断

### 2.1 漏斗节点与指标

| 节点 | 指标 | 分子 ÷ 分母 |
|---|---|---|
| 曝光 | 渠道触达量 | — |
| 投递 | 投递数 | 投递数 ÷ 曝光数（转化率低通常与 JD 或渠道有关） |
| 初筛通过 | 通过数 | 通过数 ÷ 投递数 |
| 面试到场 | 到场数 | 到场数 ÷ 邀约数 |
| 面试通过 | 通过数 | 通过数 ÷ 到场数 |
| 接受 offer | 接受数 | 接受数 ÷ offer 数 |
| 到岗 | 入职数 | 入职数 ÷ 接受数 |

数据不全时，先记起可得的部分；把每个环节的**具体数量**记下来，比只记比率更有用。

### 2.2 流失点定位表

| 流失环节 | 常见原因 | 定位方法 | 动作 |
|---|---|---|---|
| 曝光 → 投递 | JD 不吸引目标人群；渠道与岗位错配 | 按渠道看投递量差异；看岗位标题的点击表现 | 改标题与开头句；换渠道；说明业务与团队规模 |
| 投递 → 初筛通过 | 初筛标准过严；标准与渠道人群不匹配 | 各渠道通过率对比 | 放宽加分项为硬性；跨渠道统一标准 |
| 初筛通过 → 面试到场 | 邀约话术弱；通知到面试间隔太长；流程长 | 邀约接受率、间隔天数 | 缩短间隔；一次说清轮次与时长；改约时间方式 |
| 面试到场 → 面试通过 | 评价标准不清；面试官执行差异大；岗位画像没定清 | 各面试官通过率差异；同一候选人多轮是否一致 | 统一题库与评分表；校准锚点；先修画像 |
| 面试通过 → 接受 offer | 薪酬竞争力不足；决策慢；offer 条款含糊 | offer 接受率；从面试通过到 offer 的天数 | 提前定薪酬区间；压缩决策周期；offer 写清 |
| 接受 offer → 到岗 | 反悔；通勤与居住；家庭因素；接了别家 | 记录未到岗原因（问前一周） | 保持联系节奏；入职前体验与信息跟进 |

### 2.3 两个易误读的信号

| 信号 | 表面解读 | 更可能的解读 |
|---|---|---|
| 某面试官通过率显著高于其他人 | 他面得好 | 标准偏松 |
| 整体通过率很高 | 候选人质量好 | 标准太松，成本后置到绩效与离职 |
| 投递量很高但到场率低 | 岗位有吸引力 | 邀约环节弱或岗位描述与流程不符预期 |

### 2.4 诊断顺序

```
Step 1 把各环节具体数量写出来，标出数据缺口
Step 2 找出掉量明显的环节
Step 3 判断是"人不够"还是"人来了但不合格"（前者在漏斗入口，后者在评估环节）
Step 4 定位到具体环节的原因（对照上表逐项排查）
Step 5 选一个改动明显的动作，两周后复看该环节数据
```

一次只动一处，两周后看数，才能知道有没有效。同时改 JD、渠道、面试流程三处，数据变化归因不了。

## 三、小微团队轻量招聘流程

适用：团队少于 15 人，多数岗位不属于关键岗，没有专职 HR。

### 3.1 轻量方案对照

| 环节 | 标准流程 | 轻量做法 | 保留不下来的标准 |
|---|---|---|---|
| 需求确认 | 完整画像 | 使命 + 半年关键产出两项 | 使命必须写 |
| 硬性条件 | 3~5 条 | 3~5 条，不降 | 数量不省，宽松程度可以降 |
| 简历初筛 | 书面打勾 + 理由 | 同一张清单，书面留一句理由 | 书面与理由不能省 |
| 轮次 | 4~5 轮 | 2 轮（能力轮 + 老板轮） | 每轮问同一批主问题 |
| 题库 | 按胜任力分组 | 3~5 个主问题写在纸上，照问 | 主问题固定文本 |
| 评分 | 四档锚点 | 四档锚点，行为描述 | 锚点行为化不能省 |
| 评价汇总 | 开会讨论分歧项 | 各自填完提交，异常分歧才碰 | 先写后议不能省 |
| 决定 | — | 48 小时内给结论 | 时限 |
| 背调 | 授权 + 授权核查 | 取得授权；只做与岗位相关的项 | 授权不能省 |
| 入职 | 全清单 | 薪酬构成与报到时间书面确认 | 这一步不能省 |

取舍逻辑一句话：**砍轮次，不砍评价标准**。

### 3.2 两人团队的极简版

| 角色 | 分工 |
|---|---|
| A（老板/负责人） | 需求确认、简历初筛终审、决策轮、薪酬沟通 |
| B（专业面） | 能力轮、记录与评分 |
| 共同 | 面后各自提交评分 → 当天对齐结论 → 48 小时内答复候选人 |

两个人也要分开"提供信息"和"做决定"，否则等于一个人面自己定。

### 3.3 面试官先练一次

面试官上岗前的校准动作：

1. 选一份简历（可用虚构的）。
2. 两人分别按同一张评分表独立打分。
3. 比对分数，差异大的那项就是锚点没写清的地方。
4. 补写锚点，再打一次。

这个动作通常半小时，比招错一个人便宜得多。

### 3.4 轻量流程的常见塌陷点

| 塌陷点 | 表现 | 防范 |
|---|---|---|
| 老板临时插面 | 面试当天老板直接上手 | 约定谁面哪轮；临时加入也只能问该轮主问题 |
| 简历初筛变成老板一个人看 | 标准随心情变 | 固定清单 + 书面理由 |
| 评分表被省掉 | 只在群里说"我觉得还行" | 表做短，填完提交是硬要求 |
| 岗位画像没冻结 | 面试中改需求 | 画像版本冻结，变更留记录 |
| offer 拖延 | offer 发出后等一周 | 定反馈时限，超时也回一句 |

## 四、JD 与雇主品牌写法

### 4.1 JD 结构表

| 部分 | 写什么 | 常见问题 | 建议长度 |
|---|---|---|---|
| 标题 | 岗位名 + 一句真实吸引力 | 堆"急聘/诚聘/高薪" | 一行 |
| 开头一句 | 这个岗位为什么存在、团队在做什么 | 直接写职责 | 1~2 句 |
| 关键职责 | 3~5 条，每条一个可验证的事 | 罗列 15 条 | 3~5 条 |
| 任职要求 | 硬性 3~5 条 + 加分项另列 | 加分项写成硬性 | 分两段 |
| 团队与业务 | 团队规模、业务阶段、岗位在其中的位置 | 略过 | 2~3 句 |
| 薪酬与区间 | 给区间或说清按什么定，并说明结构 | 完全不提 | 1~2 句 |
| 流程说明 | 几轮、每轮多久、多久给反馈 | 不写 | 1 句 |
| 真实性说明 | 岗位是新增还是补位、职责范围真实边界 | 不写 | 1 句 |

### 4.2 关键职责的写法

| 反例 | 正例 |
|---|---|
| 负责前端开发工作 | 负责自有产品前端的核心模块开发与性能优化，把核心页面首屏时间压到 1.5 秒以内 |
| 配合团队完成项目 | 与产品、设计、后端协同完成每两周一个可演示版本的迭代节奏 |
| 维护线上系统 | 负责线上系统的稳定性保障，建立监控与告警，缩短故障发现与恢复时间 |

判断标准：**每条职责候选人读完能想到"具体要做的事"**，还是只有抽象名词。

### 4.3 任职要求的写法

分成两段：

- **硬性（3~5 条）**：不做就基本做不成的事。
- **加分（2~4 条）**：有更好，没有也能进。

不要把"有…者优先""优先""有 X 经验者优先"混进硬性段——多数读者会把整段都当硬性看，结果是合适的人自己刷掉。

### 4.4 雇主品牌在中小企业靠具体性

有效的表达要素：
- 团队现在在做什么具体的事（产品、客户服务、业务线）。
- 这个岗位半年后要交付什么。
- 决策链短（老板直接带人）这类真实优势。
- 能拿到什么成长空间（接触面、带教机会）。
- 薪酬区间的真实范围与结构。

无效的表达（且带来信任损耗）：形容词堆叠（前景无限、平台大、氛围好）、与事实不符的规模宣称、回避薪酬区间。

原则：**面试环节一旦对不上 JD，负面传播成本远高于招聘收益**。JD 里写的每一条都要能在入职后对上。

### 4.5 JD 标题的备选写法

同一岗位，准备两三个标题版本投放，看哪个的投递质量更好：

| 版本 | 示例 |
|---|---|
| 业务向 | "电商履约系统后端工程师（负责日单量百万级链路的稳定性）" |
| 能力向 | "后端工程师（负责订单与库存核心服务设计）" |
| 团队向 | "12 人技术团队的工程师（你将独立负责一个业务域）" |

判断标题好不好，看**投递进来的简历是否更接近目标人群**，而不是看点击量。

## 五、招聘流程自检清单

- [ ] 岗位画像四项齐全，且硬性条件都通过了"去掉是否还能做成"的检验
- [ ] 排除项中没有与岗位能力无关的因素
- [ ] 胜任力 3~5 项，每项都有行为描述与考察方式
- [ ] 初筛四类标准已写清，书面记录模板就位
- [ ] 轮次表标明目的、面试官、时长、决策权
- [ ] 主问题为固定文本，追问层级已写好
- [ ] 评分表有四档行为锚点，要求先写事实再写分数
- [ ] 评价汇总规则为"先写后议、只讨论分歧项"
- [ ] 背调授权与告知流程就位，核查提问限于岗位相关项
- [ ] 入职前核查清单完成，薪酬构成已书面确认
- [ ] 漏斗各环节具体数量已记录，流失点已定位到一个
- [ ] 团队较小时已给出轻量方案，且保留评价标准
- [ ] JD 已按结构成稿，未含与能力无关的筛选条件
- [ ] 涉及个人信息处理、背调合规、录用通知效力的事项已标记需专业复核
