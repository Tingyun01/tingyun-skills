# 验收节点设计 · 验收单要素 · 整改闭环

> 用于工程与项目服务的验收环节设计。本文是文档与流程辅助，不构成法律专业意见，需人工复核。

## 一、验收节点设计方法

### 步骤 1：先把合同里的验收约定抽出来
在合同、附件、图纸、报价清单、技术规范里找这些关键词，逐条摘出来填表：

- 验收类型（分项/分部/阶段/竣工/专项）
- 验收标准（引用什么文件、什么规范、什么指标）
- 验收参与方（谁签字才算数：业主代表？监理？第三方检测？）
- 验收申请提前期（提前几天通知）
- 验收完成期限（收到申请后几天内完成）
- 逾期未验收的后果（是否视为通过、是否可申请委托验收、是否付款不受影响）
- 不通过的整改与复验规则
- 验收与付款的联动（验收通过后 X 日内支付第几次款）

> 摘不出来的地方就是争议高发区——这些空白本身就是要在履约过程中补齐的空白。

### 步骤 2：给每个节点配齐"六要素"
```
六要素 = 验什么（内容） + 依据什么（标准出处） + 谁签（签署人）
        + 什么时候申请（提前期） + 什么时候签完（期限） + 不签怎么办（后果与替代路径）
```
不签怎么办这一栏经常被漏掉。常见约定与常见补法（**具体适用性以合同约定为准**）：

| 情形 | 合同常见写法 | 流程补法（需专业人士确认效力） |
|---|---|---|
| 业主逾期不组织验收 | 视同通过 | 到期后书面催告 → 记录送达 → 申请委托第三方或按合同约定方式确认 |
| 验收不通过需整改 | 整改后重新报验 | 出具整改通知单 → 整改 → 复验记录 → 双方签认 |
| 隐蔽工程未通知即覆盖 | 按不合格处理 | 覆盖前必须书面通知并留存签认记录 |

### 步骤 3：排进时间轴
把所有验收节点挂到项目总进度上，标出每个节点的"申请提前期"和"期限"。这张表和进度款节点表是一张表的两个部分——验收节点就是付款节点的前置。

## 二、验收单 / 签证单必备要素

### 2.1 验收单必备要素（10 项）
1. **项目名称与工程地址**（与合同一致，避免张冠李戴）；
2. **合同编号 + 验收单编号**（编号不重复、可检索）；
3. **验收部位 / 范围**（精确到分部或系统，不写"整体工程"）；
4. **验收依据**（合同条款号、图纸号、国家/行业标准号、双方确认的变更单编号）；
5. **实测数据与结论**（有量化指标的填实测值：尺寸、强度、厚度、数量、电压…；有定性要求的填"符合/不符合"及说明）；
6. **遗留问题清单**（问题描述、位置、整改要求、责任人、整改期限）；
7. **附件清单**（检测报告、影像资料、图纸、材料合格证编号、整改前后对比影像）；
8. **验收结论**（合格 / 整改后合格 / 不合格；注意区分表述，避免歧义）；
9. **签署栏**（签署人姓名、职务、单位、签字/盖章、日期；签署人是否有权限要事先确认）；
10. **附件页数与骑缝确认**（多页附件防抽换）。

### 2.2 签证单（现场签证/工程变更单）必备要素（9 项）
1. 关联合同编号 + 签证单编号；
2. **签证事由与依据**（为什么发生：设计变更、现场条件变化、甲方指令、材料替换…）；
3. **签证内容**（具体事项 + 数量 + 部位）；
4. **工程量与计价方式**（数量、单价或总价、计价依据文件）；
5. **工期影响**（顺延天数 / 不影响 / 提前天数）；
6. **对其他条款的影响**（是否影响验收标准、付款节点、质保责任）；
7. **确认方式与签署人**（谁签、是否需监理/建设单位确认）；
8. **生效条件与生效日期**；
9. **双方签署栏与日期**。

> 关键提醒：签证单的签署人权限、是否需要同时取得建设单位与监理单位签认、签署形式要求（签字/盖章/骑缝），均**以合同约定和当地管理要求为准，需人工复核**，不要凭经验默认。

### 2.3 单据常见的三处硬伤
- **范围写得太笼统**："本工程验收合格" → 后续无法对应到具体争议部位；
- **依据没写清**：只有结论没有依据 → 争议时对方可主张"标准不是这个"；
- **遗留问题没闭环**：写了遗留问题但没有整改期限和复验记录 → 结算时这笔款仍会被扣。

## 三、验收不通过的整改闭环流程

```
第 1 步 登记：把不通过项写入问题台账（部位、描述、依据条款、提出方、日期）
第 2 步 定性：区分三类问题
         A 属施工方原因 → 自行整改，重报验
         B 属设计/甲方原因 → 出签证或变更，据实记录，费用与工期另行确认
         C 属标准理解分歧 → 提请第三方或监理/设计单位书面明确
第 3 步 出整改通知单：问题 + 依据 + 整改要求 + 整改期限 + 责任人（双方签字）
第 4 步 整改执行：整改过程留影（整改前/中/后三张，带时间与参照物）
第 5 步 报验复验：书面报验 + 复验记录（双方签认）
第 6 步 闭环：确认通过 → 更新验收单与问题台账 → 解除该节点的付款卡点
```

### 问题台账必备字段
| 字段 | 说明 |
|---|---|
| 问题编号 | 不重复，可被整改单引用 |
| 提出日期 / 提出人 | 谁在什么时间提的 |
| 部位 | 楼栋-楼层-轴线-系统 或房间-具体位置 |
| 问题描述 | 现象 + 实测数据（如有） |
| 依据 | 合同条款/图纸号/标准号/会议纪要编号 |
| 责任归属 | A/B/C 三类 |
| 整改要求与期限 | 做什么、做到什么标准、什么时候完成 |
| 责任人 | 姓名/班组/分包 |
| 状态 | 待确认 / 待整改 / 待复验 / 已闭环 / 挂起 |
| 闭环证据 | 整改后影像 + 复验单编号 |

### 闭环判定规则
- 只有"整改后影像"没有"复验签认"，**不算闭环**；
- 复验不通过的，问题回到第 1 步，版本号 +1，历史记录保留（不覆盖）；
- 超过整改期限未复验的，自动升级并进入周会清单。

## 四、验收推进的动作清单（对方不签时）

| 序 | 动作 | 留痕 |
|---|---|---|
| 1 | 自查是否有我方书面验收申请 | 申请单 + 发送记录 |
| 2 | 无申请 → 补做完整验收申请（写明交付内容、依据、请求确认期限） | 申请单 + 送达凭证 |
| 3 | 有申请 → 书面催告函（引用合同验收条款 + 申请日期 + 请求期限 + 逾期处理方式） | 催告函 + 送达凭证 |
| 4 | 到期仍无回应 → 记录"逾期未回复"，按合同约定路径推进（是否可视为验收通过、如何确认，需专业人士审阅） | 书面记录 + 时间线 |
| 5 | 对方书面拒签 → 记录拒签理由与依据，逐条比对合同标准，出差异说明 | 拒签函 + 差异说明 |
| 6 | 差异说明不被接受 → 提请第三方检测/监理或设计单位明确；同步评估争议解决路径 | 第三方/监理书面意见 |

**红线**：不代签验收单、不伪造签收或复验记录、不倒填日期、不把"我方签了对方没签"解释成对方已认可。签名与签认的效力问题需人工复核。

## 五、验收阶段自检（每月/每节点跑一次）

1. 每个验收节点是否都有"标准出处 + 签署人 + 期限"三件套？
2. 已完成但未签验的节点有哪几个？卡在谁那里？
3. 问题台账里还有多少条未闭环？超期的是哪几条？
4. 隐蔽工程有没有"覆盖前通知 + 签认 + 影像"三件套齐全的？
5. 验收单上的遗留问题，是否都已有复验闭环记录？
6. 有没有节点已过期（过了合同约定验收期限）但台账还标"待验收"？
